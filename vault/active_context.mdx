# Active Context

## 当前唯一优先级

**Combo — 验证“垂类创作者 AI 服务产品化”能否形成真实收入闭环**

当前公司定义：

> Combo 帮助垂类创作者，把反复提供的专业服务变成可收费、可规模化交付的 AI 产品。

当前阶段是**带有平台期权的创作者变现工具**，不是已经成立的 Agent Marketplace。Agora 保留为长期平台机制与历史研究代号。

战略表达与当前经营事实必须分开：

- **Category（未来 thesis）**：`AI-native Service Commerce`
- **Wedge（当前产品楔子）**：`Agent Miniapp / AI Service Launcher for Provider-owned Practices`
- **Target Platform（条件式目标）**：`AI-native Practice Operating & Exchange Network`
- **连续主线**：`Launcher → Practice OS → Service Extension Economy → 条件式 Demand / Infrastructure / Agent Procurement`

32 轮战略复审已完成 Phase 2，状态为 `strategic-review-complete-phase-2`。这只表示未来故事与最强反方已被系统化，不表示真实付费、留存、Partner 经济、平台资格或 investment-ready 已成立。

## 当前角色与目标路径

- 垂类创作者 / KOL：Combo 的客户、能力供给者和首阶段分发者
- 粉丝：具体 AI 服务的最终消费者
- Combo：目标上承担能力提取与封装、Runtime、权限、计量、支付、结果交付与售后；完整交易体验和履约质量仍待真实订单验证
- 首阶段目标路径：`创作者内容 / 主页 / 私域 → 一个明确 AI 服务 → 粉丝付费 → 结果与反馈`

## 当前需要证明的四件事

1. **供给成立**：哪一类创作者真正需要增量变现，并愿意上线和持续维护 AI 服务。
2. **产品成立**：哪一种服务既依赖专业经验，又足够重复、可验证、可控风险。
3. **需求成立**：通用模型已经存在时，粉丝为什么仍愿意单独付费并再次回来。
4. **经济成立**：售价、推理与工具成本、支付费、分成、退款、补贴和售后之后，贡献毛利是否为正。

## 当前执行目标

- 只选一个垂类，不并列测试创作、交易、占卜等不同逻辑
- 与 3–5 个创作者完成真实产品共创与上线
- 每个服务只有一个明确结果、一个入口、一个价格
- 做出一个 60 秒内可感知差异的 Before / After Demo
- 建立唯一漏斗：触达 → 同意共创 → 上线 → 点击 → 使用 → 付费 → 完成 → 退款 → 7/30 日复购 → 第二个产品
- 用真实数据填写单任务经济模型，不再用 Marketplace 五年推演代替当前经营事实

## 最近已验证的产品表面

- 2026-08-03 对公开 Combo Knowledge Agent 做了四轮黑盒调用：`knowledge_grounded`、`general_reasoning` 与 `insufficient_evidence` 三种可见模式能够分流，并维持连续会话
- 该结果只证明公开问答 surface 的最小行为和 evidence routing；不证明 citation 精确性、长期记忆、并发、生产 SLA，也不替代付费服务闭环

## 平台跃迁门槛

当前故事可以描述条件式平台未来，但只有出现以下证据，才把 Combo 描述为**已成立的平台**：

0. **Practice OS 连续性**：Provider 在订单之间持续经营多项 Service Product，并对同一经营对象与状态产生 recurring WTP；
1. **Extension Economy**：独立 Partner 围绕同一 Service Object 一次开发、多家 Practice 获益，并形成可持续 Partner P&L 与治理；
2. **跨创作者复用**：同一用户购买第二、第三个服务，并复用已授权 Context；
3. **新增需求**：Combo 能给 Provider 带来私域之外的新增付费需求，形成平台内生 GMV；
4. **路由变好**：Context、运行结果、退款和评价持续改善跨服务路由与组合。

## 阻塞项 / 未决策

- 首轮验证候选已收敛为“AI 原生专业视觉创作者”，但第一个具体服务结果、共创名单和付费成立与否尚未确认；它是测试选择，不是已验证的最终市场结论
- 暂无 Combo 自己的真实付费、退款、复购和贡献毛利数据
- Provider 是否在订单之间持续使用同一经营系统、是否愿意持续付费，仍无 cohort 证据
- Service Extension Economy、Partner P&L、需求所有权与跨 Provider 复用均是未来 thesis
- 支付、数据授权、隐私删除、跨境结算与高风险服务边界仍需形成明确方案

## 表达纪律

- “创作者意向”不能写成“已上线”或“已拿下”
- 外部类比和测算不能写成 Combo 真实数据
- Coding Session 只是能力导入方式之一，不是公司定义
- KOL 私域解决首次触达，不自动解决留存与壁垒
- Agent 数量、Feed 或 Marketplace 页面不等于网络效应
- 不使用“完整复制一个人”“偷数据”“灰色支付”等不准确或高风险表达
