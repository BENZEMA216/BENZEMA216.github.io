# Agora Financial Model — BP 工作稿

> [!warning] 历史情景模型
> 本文的 Marketplace、GMV、take rate、融资额与五年预测均为旧平台假设，不是 Combo 当前经营事实。当前先以单任务经济模型和真实漏斗校准，见 [combo-unit-economics-v0-2026-07](/output/reports/combo/business-model/combo-unit-economics-v0-2026-07/)。

> 估算日期：2026-04-29  
> 口径：融资 BP 模型，不是审计预测或投资建议。模型的作用是解释 Agora 的收入引擎、成本结构、融资节奏和关键验证指标。

## 1. 核心结论

Agora 不应该被建模成纯 SaaS，而应该建模成 **Agent 能力包 marketplace + creator tooling + trust/settlement infrastructure**。

最重要的财务变量不是创作者数量，而是：

1. 付费用户数
2. 每个付费用户每月在能力包上的 GMV
3. 平台 take rate
4. 能力包迁移成功率和复购率

Base case 下：

| 指标 | Y1 | Y2 | Y3 | Y4 | Y5 |
|---|---:|---:|---:|---:|---:|
| Avg monthly paid users | 2,000 | 30,000 | 200,000 | 750,000 | 2,000,000 |
| Monthly GMV / paid user | $20 | $25 | $35 | $45 | $55 |
| Marketplace GMV | $0.48M | $9.0M | $84.0M | $405.0M | $1.32B |
| Take rate | 10% | 10% | 12% | 13% | 13% |
| Total net revenue | $0.15M | $1.35M | $11.43M | $56.65M | $183.10M |
| Gross margin | 73% | 78% | 81% | 83% | 85% |
| EBITDA | -$3.79M | -$6.96M | -$9.49M | $3.52M | $61.04M |

这个模型的含义是：**Seed $5M 足够验证供给和交易闭环，但不够支撑 Y2 之后的规模化扩张。** Base case 里需要在 12-18 个月内启动 Series A；如果 seed 期刻意压低 GTM 和 headcount，runway 可以延长到 18-24 个月。

## 2. 收入模型

### 2.1 Marketplace Take Rate

用户购买 credits 或直接支付能力包费用，创作者自主设置价格，Agora 抽取交易费。

早期建议 take rate：

| 阶段 | Take rate | 原因 |
|---|---:|---|
| Y1-Y2 | 10% | creator-friendly，优先冷启动高质量供给 |
| Y3 | 12% | trust、testing、billing、distribution 价值开始显性化 |
| Y4-Y5 | 13% | 平台承担更多审核、支持、争议处理、推荐和分账职责 |

不要一开始做 20-30% take rate。Agora 需要先证明“发布能力包能赚钱”，创作者侧的激励比平台早期收入更重要。

### 2.2 Creator SaaS / Certification

Agora 可以向创作者收：

- Publisher Pro
- canonical tests 生成与托管
- certification / security review
- featured listing
- creator analytics
- private beta distribution

这部分不是主收入，但能在 marketplace GMV 起量前给 BP 一个合理的 early revenue bridge。

### 2.3 Platform-owned Lighthouse Packages

Y1-Y2 需要平台自建或共建少数标杆能力包，原因不是为了长期做内容公司，而是为了：

- 证明 package publisher 可以工作
- 证明用户愿意付费
- 给第三方创作者一个可模仿的质量标准
- 用真实交易数据训练 pricing、ranking、refund、support 机制

这部分收入在绝对值上可以增长，但占比应该下降。

## 3. 成本模型

### 3.1 COGS

Agora 的毛利应该比 token resale 更好，因为模型成本原则上由用户 BYOK、pass-through 或能力包价格承担。平台主要 COGS 是：

- payment fee
- fraud / refund / dispute
- cloud registry、logs、observability
- support and trust operations
- package verification infrastructure

Base case 用 73% → 85% gross margin。早期毛利低，是因为人工支持、创作者共创、失败任务和退款都会更重。

### 3.2 Opex

早期最大成本不是服务器，而是：

1. 工程团队：publisher、runtime adapter、registry、billing、trust layer
2. creator ops：共创能力包、补贴、质量审核
3. GTM：KOL、创作者社群、内容、case study
4. legal / payment / compliance：跨境分账、税务、隐私、安全责任边界

Base case opex：

| 指标 | Y1 | Y2 | Y3 | Y4 | Y5 |
|---|---:|---:|---:|---:|---:|
| Avg FTE | 10 | 22 | 45 | 90 | 160 |
| Headcount expense | $1.70M | $3.96M | $8.55M | $18.00M | $33.60M |
| Creator incentives | $0.80M | $1.20M | $2.50M | $5.00M | $10.00M |
| GTM / creator acquisition | $0.50M | $1.50M | $5.00M | $15.00M | $40.00M |
| Infra / security / compliance opex | $0.50M | $0.75M | $1.50M | $3.00M | $6.00M |
| Legal / finance / admin | $0.40M | $0.60M | $1.20M | $2.50M | $5.00M |
| Total opex | $3.90M | $8.01M | $18.75M | $43.50M | $94.60M |

## 4. Scenario Analysis

| Scenario | Y5 paid users | Y5 monthly GMV/user | Y5 GMV | Y5 net revenue | Y5 EBITDA | 解释 |
|---|---:|---:|---:|---:|---:|---|
| Conservative | 350K | $35 | $147M | $21.64M | -$17.26M | 能力包市场存在，但复购和用户扩张不足，仍是小众 creator tooling |
| Base | 2.0M | $55 | $1.32B | $183.10M | $61.04M | 出现多个垂直类目，能力包成为 AI 高级用户的常规购买方式 |
| Upside | 5.0M | $80 | $4.80B | $775.00M | $454.25M | Agent runtime 普及，Agora 成为跨 runtime 能力分发网络 |

Conservative case 的意义是提醒我们：如果只有创作者发布，没有真实付费复购，Agora 会停在工具层，不能成为 VC-scale marketplace。

Upside case 的意义是：一旦 Agent runtime 成为个人和企业工作流入口，能力包会像 app、插件、template 和 workflow 的混合体一样扩散，GMV 可以出现非线性增长。

## 5. Seed 融资与里程碑

建议 BP 口径：

**Seed $5M / Pre-money ~$25M / 18-24 个月 runway。**

这笔钱不是用来承诺做到大规模收入，而是用来验证 marketplace 的四个底层假设：

| 里程碑 | Seed 阶段目标 |
|---|---|
| Supply | 20-50 个可发布能力包，5-10 个标杆能力包 |
| Migration | 能力包在 canonical tests 上迁移成功率 >60-70% |
| Demand | 1,000-3,000 个付费用户，或等价的强 waitlist / pre-order |
| Economics | 月 GMV / paid user >$20 |
| Retention | 付费用户 M2 repeat >30-40% |
| Creator proof | 至少 1 个创作者月收入 >$1K，后续目标 >$5K |

Series A 触发条件不应该只写 ARR，而应该写：

- $100K-$250K monthly GMV
- $10K-$30K monthly net revenue
- GMV 连续增长
- 付费用户复购成立
- 能力包迁移成功率稳定
- 供给侧出现 creator earning case study

## 6. BP 里应该怎么讲

一页 slide 可以这样表达：

**Agora captures value as the distribution and trust layer for Agent capability packages.**

- Users pay for outcome-oriented capability packages.
- Creators monetize reusable agent know-how.
- Agora takes 10-13% of GMV and sells publishing / testing / certification tools.
- Inference cost is mostly pass-through or user-paid, so Agora avoids token resale economics.
- The model becomes powerful when agent runtime adoption drives J-curve growth in paid usage.

最重要的表述是：**我们不是靠卖 token 赚钱，而是靠把 Agent 能力变成可交易生产资料赚钱。**

## 7. 关键风险

| 风险 | 监控指标 | 应对 |
|---|---|---|
| 用户只试用不复购 | M2 repeat、monthly GMV/user | 先做结果明确、频次高的垂直类目 |
| 创作者上架但赚不到钱 | creator payout、active paid creators | 平台共建 lighthouse packages，早期给保底和流量 |
| 能力迁移失败 | canonical tests pass rate、refund rate | package compiler + context distillation + runtime compatibility matrix |
| COGS 被 support 拖高 | ticket / paid run、refund / GMV | 强化自助安装、运行日志、失败归因 |
| 大厂 marketplace 进入 | creator retention、cross-runtime installs | 坚持开放、cross-runtime、creator sovereignty 和本地执行场景 |

## 8. 外部 benchmark

这些 benchmark 只用于校准，不代表 Agora 应直接照搬：

- [Stripe Pricing](https://stripe.com/pricing)：支付成本是 marketplace 模型的底层变量；跨境、退款、争议和税务会让实际成本高于 headline card processing。
- [Apple App Store Small Business Program](https://developer.apple.com/app-store/small-business-program/)：消费级 app marketplace 的平台费可以到 15% 或更高，但 Agora 早期应保持 creator-friendly。
- [Microsoft commercial marketplace transaction capabilities](https://learn.microsoft.com/en-us/partner-center/marketplace-offers/marketplace-commercial-transaction-capabilities-and-considerations)：低接触 B2B marketplace 可以用较低 transaction fee，但 Agora 早期会承担更多 trust、runtime、support 和 creator ops。
- [Gartner AI Agents Forecast](https://www.gartner.com/en/newsroom/press-releases/2025-08-26-gartner-predicts-40-percent-of-enterprise-apps-will-feature-task-specific-ai-agents-by-2026-up-from-less-than-5-percent-in-2025)：Agent 会快速进入企业应用主流程。
- [McKinsey Generative AI Economic Potential](https://www.mckinsey.com/capabilities/mckinsey-digital/our-insights/The-economic-potential-of-generative-AI-The-next-productivity-frontier)：AI 的经济价值来自具体业务流程自动化，支撑 Agora 从“生产资料市场”角度建模。
