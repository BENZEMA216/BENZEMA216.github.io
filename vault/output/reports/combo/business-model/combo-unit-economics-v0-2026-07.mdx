# Combo 单任务与单创作者单位经济模型 v0

> 目的：在真实付费数据出现前，先统一每一单、每一位创作者的收入与成本口径。本文是可填写的决策模板，不是财务预测。

## 0. 当前结论与硬边界

Combo 当前应按“创作者变现工具”核算，而不是用未来 Marketplace 的规模假设倒推今天的经济模型：

> Combo 帮助垂类创作者，把反复提供的专业服务，变成可收费、可规模化交付的 AI 产品。

本模型遵守四条规则：

1. **不把融资 Pitch 中的测算写成事实。** `15%` 平台抽成、`2%` 付费转化、粉丝数、客单价和复购率都只是待验证假设。
2. **不只算模型 Token。** 每单必须纳入推理、工具/API、Sandbox、支付、退款损失、失败重跑和可变支持成本；这与 [agent-runtime](/wiki/concepts/agent-runtime/) 所强调的持续履约责任一致。
3. **创作者分成不是平台收入。** 必须先从实际成交额中扣除创作者应得收入，再讨论平台净收入和贡献毛利。
4. **私域流量不等于零 CAC。** 即使没有广告费，创作者建联、共创、内容发布、首单运营和团队时间仍然是获客成本。

截至 `2026-07-17`，Combo 尚无足够真实订单支持填写稳定基准值。下文所有 `[待填]` 必须来自订单、支付、Runtime 或人工工时记录。

## 1. 模型对象与统计窗口

### 1.1 三个核算对象

| 层级 | 核心问题 | 最小统计单位 |
|---|---|---|
| 单任务 | 每完成一次交付，平台是否创造正贡献利润？ | 一次付费任务尝试 |
| 单创作者 | 一位创作者带来的订单，能否覆盖建联与共创成本？ | 创作者 × 固定观察窗口 |
| 单垂类 | 多位创作者是否重复出现相似的正向经济模型？ | 同一垂类的 3–5 位创作者 |

本文重点处理前两层；垂类验证方法见 [combo-one-vertical-validation-2026-07](/output/reports/combo/gtm/combo-one-vertical-validation-2026-07/)。

## 2. 单任务经济模型

### 2.1 变量定义

| 符号 | 字段 | 定义 | 数据来源 |
|---|---|---|---|
| `P` | 售价 | 用户实际支付的单任务价格，不含代收税费 | 支付订单 |
| `R` | 实际退款本金 | 该笔订单全额或部分退款的真实金额，不用“退款订单比例”代替金额 | 退款记录 |
| `G` | 实现实收 GMV | 扣除退款本金后的实际成交额 | 支付与退款对账 |
| `B` | 平台抽成基数 | 实验开始前约定的平台收费基数；不得与实收 GMV、服务加价混称 | 创作者协议 |
| `t` | 平台抽成率 | 平台计划收入相对 `B` 的比例；`15%` 目前只是候选假设 | 创作者协议 |
| `Creator Payout` | 创作者实际结算额 | 按协议和支付对账记录，不用平台抽成率冒充创作者分成率 | 分账记录 |
| `C_infer` | 推理成本 | 模型输入、输出、图片/视频生成及重试成本 | 模型调用日志 |
| `C_tool` | 工具/API 成本 | 搜索、抓取、存储、第三方生成或专业 API | 工具调用账单 |
| `C_sandbox` | Sandbox 成本 | 容器启动、运行时长、网络、文件与临时存储 | Runtime/Sandbox 日志 |
| `C_pay` | 支付费 | 通道费、固定手续费、跨境费及不可退回手续费 | 支付渠道账单 |
| `C_refund_ops` | 退款与争议成本 | 退款本金之外的不可回收手续费、争议费和人工处理 | 支付与客服记录 |
| `C_support` | 可变支持成本 | 单次失败重跑、人工补交付、客服和审核工时 | 工单与工时记录 |
| `C_subsidy` | 额外平台补贴 | 未包含在用户实付、创作者结算额或其他成本中的平台额外现金激励 | 优惠券与活动账本 |
| `C_other` | 其他可变成本 | 与订单量直接相关、但不属于上述项目的成本 | 成本凭证 |

`[context-container](/wiki/concepts/context-container/)` 涉及的私域数据存储、脱敏与权限成本，如果会随每单发生，应进入 `C_tool`、`C_sandbox` 或 `C_other`，不得留在“未来安全成本”中忽略。

### 2.2 Gross-to-net 公式

以一笔实际订单为例：

```text
结账 GMV                  = P
实际退款本金              = R
实现实收 GMV（G）          = P − R

平台计划收入                  = B × t
创作者收入（Creator Payout） = 按预先约定的结算规则计算，并以实际分账校准
平台净收入（Net Revenue）    = G − Creator Payout
实际平台抽成率                = Net Revenue ÷ B

运行成本（C_run）           = C_infer + C_tool + C_sandbox
交易成本（C_txn）           = C_pay + C_refund_ops
履约成本（C_fulfill）        = C_support + C_other

单任务贡献利润（CM$）          = Net Revenue − C_run − C_txn − C_fulfill − C_subsidy
每 GMV 贡献率（CM/GMV）       = CM$ ÷ G
平台贡献毛利率（CM%）          = CM$ ÷ Net Revenue
```

注意：退款本金已通过 `G` 扣除，`C_refund_ops` 只能记录退款后仍损失的手续费、争议费和人工成本，避免重复扣减。`C_subsidy` 也只记录尚未反映在 `P` 或 `Creator Payout` 中的额外支出；若优惠已降低用户实付，或平台补足金额已进入创作者实际结算额，不得再次扣减。若订单还包含代收税费、应付第三方款项或纯成本透传，应单独列示并对账，不能把它们误报为平台收入或创作者收入。比例指标必须处理零值边界：`B ≤ 0` 时实际平台抽成率记为 `N/A`，`G ≤ 0` 时 `CM/GMV` 记为 `N/A`，`Net Revenue ≤ 0` 时平台 `CM%` 记为 `N/A` 并直接判定该订单口径不可扩量；不得计算无意义的零分母或反向百分比。

### 2.4 失败任务不能被隐藏

每个任务版本至少分别统计：

| 任务结果 | 收入处理 | 成本处理 |
|---|---|---|
| 首次成功交付 | 计入实收 | 计入完整运行成本 |
| 自动重试后成功 | 计入实收 | 所有重试成本均计入 |
| 人工补交付后成功 | 计入实收 | 人工工时计入 `C_support` |
| 用户退款 | 从实收扣除 | 已发生的运行、支付和支持成本仍保留 |
| 平台主动免单 | 计为平台补贴 | 所有可变成本仍保留 |
| 创作者亲自接管 | 只有事先定义为升级服务时才算正常交付 | 创作者和平台人工成本均需记录 |

这能防止把 [human-in-the-loop](/wiki/concepts/human-in-the-loop/) 所需的真人补位误报成“纯 AI 自动交付”。

## 3. 定价与分成：需要验证，不预设答案

### 3.1 两种可测试结构

| 结构 | 公式 | 优点 | 风险 |
|---|---|---|---|
| 全包价 | 用户支付一个最终价格，按约定基数分成 | 用户理解简单 | 高成本任务会侵蚀创作者或平台收入 |
| 成本透传 + 服务加价 | 基础运行成本透明透传，只对服务价值部分分成 | 不对推理成本重复抽税 | 页面和结算更复杂，需要用户理解成本构成 |

每位创作者、每个任务版本只能选择一种结构，并在实验前登记。不要因为某次任务成本高，就临时改变分成口径。

### 3.2 `15%` 的正确状态

`15%` 目前只应记录为：

```yaml
claim: 平台可能按成交额抽取 15%
status: hypothesis
validated: false
required_evidence:
  - 创作者接受度
  - 平台承担的真实履约与售后责任
  - 该抽成下的单任务贡献利润
  - 与替代变现方式的创作者净收入比较
```

只有在创作者愿意持续发布、平台能承担 Runtime/支付/售后且双方均获得正向经济回报后，才可以将某个抽成范围升级为已验证口径。

## 4. 单创作者经济模型

### 4.1 创作者级变量

| 字段 | 定义 | 不能遗漏的内容 |
|---|---|---|
| `CAC_creator` | 获取一位合格创作者并使其进入共创的成本 | 建联、销售、差旅、渠道佣金、失败候选人的分摊成本 |
| `C_cocreate` | 从需求定义到首个可售产品上线的共创成本 | 产品、Prompt、设计、数据清洗、测试、Creator review、上架 |
| `C_maintain` | 观察窗口内的维护成本 | 更新、质量回归、内容审核、创作者沟通 |
| `CAC_buyer_cash` | 获得一位首次付费用户的现金成本 | 广告、联盟分成、优惠券、付费内容 |
| `CAC_buyer_full` | 获得一位首次付费用户的完全成本 | 现金 CAC + 可归因运营工时；私域也必须计算 |
| `N_paid` | 付费订单数 | 去重用户数和订单数分别记录 |
| `N_repeat` | 复购订单数 | 区分同一任务、同一创作者其他任务、跨创作者购买 |
| `Creator Payout` | 创作者实际到账 | 扣除退款、税费和延期结算后分别展示 |
| `Creator Effort` | 创作者投入时间 | 共创、审核、发布、客服、真人接管 |

### 4.2 创作者级公式

```text
观察窗口贡献利润
= Σ 单任务贡献利润
− CAC_creator
− C_cocreate
− C_maintain
− 无法归因到单笔订单的消费者获客成本

共创回收订单数
= (CAC_creator + C_cocreate) ÷ 代表性单任务贡献利润

创作者有效时薪
= 创作者实际到账 ÷ 创作者总投入小时

平台每创作者回报
= 观察窗口贡献利润 ÷ (CAC_creator + C_cocreate)
```

如果代表性单任务贡献利润小于或等于零，“共创回收订单数”没有意义，应先停止扩量并修正定价、任务边界或成本。

## 5. 决策阈值

在获得第一批真实订单前，不设看似精确的行业基准。每轮实验必须预先登记四个阈值变量：

| 阈值 | 含义 | 本轮预登记 |
|---|---|---|
| `T_CM$` | 可接受的最低单任务贡献利润 | `[待填]` |
| `T_CM/GMV` | 可接受的最低每 GMV 贡献率 | `[待填]` |
| `T_CM%` | 可接受的最低平台贡献毛利率（分母为 Net Revenue） | `[待填]` |
| `T_refund` | 可接受的最高退款率 | `[待填]` |
| `T_payback` | 可接受的最长创作者共创回收周期 | `[待填]` |

### 红灯：停止扩量

- 观察到的代表性单任务 `CM$ ≤ 0`。
- 在调整一次价格或任务边界后，完整成本口径仍为负。
- 退款、失败重跑或人工补交付使 `CM/GMV` 或 `CM%` 低于对应预登记阈值。
- 创作者收入不足以覆盖其真实投入，且不愿再次发布。
- 只有在平台补贴或不计团队工时的情况下模型才成立。

### 黄灯：继续小样本学习，不对外宣称成立

- 单任务贡献为正，但尚无法在观察窗口内回收创作者建联与共创成本。
- 收入集中在一位创作者或一次异常传播，无法跨创作者复现。
- 有首单但没有复购观察窗口，或复购仅靠人工追单。
- 平台抽成需要创作者接受度和真实售后责任进一步校准。

### 绿灯：允许扩大同垂类验证

- 多位创作者的代表性订单在完整成本口径下贡献为正。
- 在实际退款和高成本任务情景下仍不跌破预登记阈值。
- 创作者获得有意义的净收入，并愿意继续发布或更新产品。
- 观察到自然复购，且共创成本存在可解释的回收路径。

绿灯只意味着可以扩大同一垂类，不意味着 Marketplace 或平台网络效应已经成立。

## 6. 假设登记表

| 假设 | 当前状态 | 证据要求 | 禁止的表达 |
|---|---|---|---|
| 平台抽成 `15%` 可被创作者接受 | 待验证 | 真实协议、持续发布、创作者净收入 | “Combo 已确定抽成 15%” |
| 私域触达后的付费转化为 `2%` | 待验证 | Combo 自身的合格触达→付费漏斗 | “行业已经证明 2%” |
| 推理成本约占售价的固定比例 | 待验证 | 按任务版本记录的真实调用账单 | 用单次 Demo 成本外推全部订单 |
| KOL 私域意味着低 CAC | 待验证 | 建联、共创、内容和补贴完全成本 | “私域获客免费” |
| 低价 AI 服务会产生复购 | 待验证 | 7/30 日 cohort | 用首次尝鲜代替复购 |
| 用户愿意为创作者方法而非免费 AI 付费 | 待验证 | 真实支付、基线对比与退款原因 | 用粉丝信任直接推导付费 |

## 8. 每周复盘输出

每周只回答五个问题：

1. 哪类任务在完整成本口径下贡献为正？
2. 成本最大的不确定项是推理、工具、Sandbox、退款，还是人工补交付？
3. 哪位创作者已经回收建联与共创成本？
4. 用户为什么退款、为什么复购？
5. 哪个数字仍是代理假设，尚未被 Combo 自身数据替换？

只有当这些答案来自真实订单，单位经济模型才能从 `hypothesis` 升级为 `observed`。
