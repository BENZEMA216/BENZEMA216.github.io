# Combo 单垂类验证计划：AI 原生专业视觉创作者

> 目标：用同一垂类的 3–5 位创作者，验证一个具体 AI 服务能否完成“上线—真实触达—付费—交付—退款/复购—贡献毛利”的闭环，而不是继续用 Marketplace、Feed 或平台想象代替单点证据。

## 0. 验证命题

当前公司定义：

> Combo 帮助垂类创作者，把反复提供的专业服务，变成可收费、可规模化交付的 AI 产品。

本轮只验证一个命题：

> AI 原生专业视觉创作者的粉丝，是否愿意为“创作者方法论驱动的视觉作品诊断与可执行改进方案”真实付费，并在交付后满意、少退款、产生再次使用需求。

候选服务暂定为：

### AI 视觉作品诊断与改进包

用户输入：

- 一张待发布或待修改的视觉作品；
- 使用场景与目标受众；
- 可选的参考图、风格和限制条件。

用户在 60 秒内获得：

- 按该创作者方法论生成的视觉诊断；
- 三个按优先级排序的核心问题；
- 可直接执行的修改指令、Prompt 或工作步骤；
- 一份可视化标注对比或改版预览；
- 明确说明哪些复杂需求需要升级到真人服务。

这是待验证的服务定义，不代表需求已经成立。它结合了 [creative-agent-design](/wiki/concepts/creative-agent-design/) 的专业判断、[genui](/wiki/concepts/genui/) 的结果可视化和 [human-in-the-loop](/wiki/concepts/human-in-the-loop/) 的真人升级边界。

## 1. 为什么只选这个垂类

选择“AI 原生专业视觉创作者”作为首轮垂类，是因为它同时具备待验证的有利条件：

- 团队在视觉创作 Agent 和专业创作者生态上有直接经验与建联基础；
- 输入和输出容易形成可展示的 Before/After；
- 任务可以在相对明确的边界内交付；
- 相比交易、医疗、法律等场景，监管和重大损害风险更低；
- 创作者已有内容渠道，可直接测试私域/内容触达；
- 创作者的品味与判断可能形成相对通用模型的差异，但这个差异必须通过对照实验而非口头主张证明。

本轮明确不做：

- 不同时测试交易、占卜、咨询或其他垂类；
- 不做 Agent Marketplace、Feed 或公域推荐；
- 不承诺完整复制创作者本人；
- 不把 Coding Agent Session 当作唯一导入方式；
- 不用创作者数量、Agent 数量或注册用户数证明平台成立；
- 不把免费试用、补贴订单或建联意向当成真实付费验证。

## 2. 任务筛选六条件

最终上线的任务必须同时通过六个条件。任何一项没有证据，都标为待验证，不得用团队直觉代替。

| 条件 | 通过标准 | 所需证据 | 失败信号 |
|---|---|---|---|
| 1. 已存在真实重复需求 | 创作者过去持续收到同类作品点评、改稿或方法咨询 | 私信/评论匿名计数、历史订单、访谈原话 | 需求主要由团队教育出来，过去几乎没人询问 |
| 2. 创作者专业性带来差异 | 目标用户或盲评者能识别其结果优于免费通用 AI 基线 | 同输入 A/B 结果、Creator review、用户选择原因 | 去掉创作者名字后，结果与通用模型无显著差异 |
| 3. 任务可被半标准化 | 输入、输出、权限、失败边界和交付时间可以预先定义 | Task contract、canonical examples、失败案例 | 每单都必须由创作者重新判断和亲自交付 |
| 4. 结果可快速感知与验证 | 60 秒内出现明确诊断和可执行 Before/After | Demo 录像、交付样例、用户复述 | 只能输出泛泛建议，用户无法判断是否变好 |
| 5. 有复购或相邻需求 | 同一用户可能在下一张作品、下一次发布或下一阶段再次使用 | 历史任务频次、7/30 日行为、相邻请求 | 纯一次性尝鲜，完成后没有再次触发场景 |
| 6. 安全且经济上可交付 | 权利边界清楚、风险可控，完整可变成本有正贡献路径 | 授权确认、成本记录、退款规则、单位经济模型 | 涉及未授权素材/隐私，或只有忽略人工与失败成本才盈利 |

任务通过六项后才进入收费测试；否则先调整任务，不扩大创作者数量。

## 3. 3–5 位创作者样本设计

### 3.1 样本边界

|---|---|---|---|---|
| Creator A | `[待填]` | `[待填]` | `[待填]` | 候选/合格/共创/上线 |
| Creator B | `[待填]` | `[待填]` | `[待填]` | 候选/合格/共创/上线 |
| Creator C | `[待填]` | `[待填]` | `[待填]` | 候选/合格/共创/上线 |
| Creator D | `[可选]` | `[待填]` | `[待填]` | 候选/合格/共创/上线 |
| Creator E | `[可选]` | `[待填]` | `[待填]` | 候选/合格/共创/上线 |

### 3.2 创作者准入条件

- 过去存在可追溯的重复咨询、点评、改稿或人工服务需求；
- 愿意提供最小必要的公开内容、方法步骤或授权样例，而非上传全部历史记录；
- 愿意审核任务合同、正反例和失败边界；
- 愿意通过自己的真实渠道完成至少一次可追踪发布；
- 同意披露给平台的工时、收入和退款数据，用于匿名化复盘；
- 愿意在测试后明确回答是否继续发布、更新或制作第二个产品。

只有表达兴趣、没有提供样例和发布承诺的创作者，应记为“意向”，不能称为“拿下”。

## 4. 单一任务合同

每位创作者上线前必须共同确认同一份结构化合同：

| 项目 | 必填内容 |
|---|---|
| 用户任务 | 用户到底想改善哪一张视觉作品、用于什么场景 |
| 必要输入 | 图片、目标、受众、参考、限制条件 |
| 不必要输入 | 完整手机、全部聊天、全部 Session 等高权限数据 |
| 输出承诺 | 诊断、优先级、修改动作、可视化对比 |
| 非承诺 | 不保证爆款、商业转化或审美唯一正确 |
| 创作者独特方法 | 可描述、可测试但不公开泄露的判断步骤 |
| 通用 AI 基线 | 使用同一输入运行的免费/通用模型版本 |
| 成功标准 | 用户能理解问题、采取修改并认为结果有价值 |
| 失败条件 | 输入不足、版权不清、任务越界、运行失败 |
| 真人升级 | 什么情况转给创作者，是否额外收费 |
| 退款条件 | 未交付、严重偏题、技术失败及其他明确条件 |
| 数据处理 | 最小收集、保存周期、删除与创作者授权 |

“完整复制创作者”不是合同目标；目标是把一个重复服务的方法与边界产品化。

## 5. 唯一漏斗

本轮所有创作者使用同一漏斗和事件命名，禁止每人选择对自己有利的分母。

```text
创作者候选
→ 合格创作者
→ 完成共创
→ 成功上线
→ 合格触达
→ Landing Visit
→ Task Start
→ Checkout Start
→ Paid Order
→ Delivered
→ Accepted / No Refund
→ 7 日复购
→ 30 日复购
→ 跨创作者购买（仅观察平台前置信号）
```

### 5.1 事件定义

| 事件 | 唯一定义 | 关键字段 |
|---|---|---|
| 合格触达 | 创作者真实内容/主页/私域中，可追踪且面向目标受众的曝光；不能直接使用粉丝总数 | creator、channel、campaign、unique reach |
| Landing Visit | 用户打开该创作者的具体服务页 | anonymous_user、creator、campaign |
| Task Start | 用户提交第一个有效输入，而非只看页面 | task_version、input_valid |
| Checkout Start | 用户进入真实支付流程 | price、discount、currency |
| Paid Order | 支付渠道确认收款；免费券需单独标记 | order_id、cash_paid、subsidy |
| Delivered | 系统按任务合同输出完整结果 | run_id、latency、cost、retries |
| Accepted | 退款观察窗结束且未全额退款 | refund_status、reason |
| 7/30 日复购 | 同一用户在对应窗口内再次真实付费 | same_task / same_creator / cross_creator |
| 跨创作者购买 | 用户购买第二位不同创作者的服务 | first_creator、second_creator、route_source |

### 5.2 核心转化指标

| 指标 | 公式 |
|---|---|
| 创作者上线率 | 成功上线创作者 ÷ 合格创作者 |
| 触达点击率 | Landing Visit 去重用户 ÷ 合格触达人数 |
| 激活率 | Task Start 去重用户 ÷ Landing Visit 去重用户 |
| 支付启动率 | Checkout Start 去重用户 ÷ Task Start 去重用户 |
| 真实付费率 | Paid User ÷ Task Start 去重用户 |
| 触达付费率 | Paid User ÷ 合格触达人数 |
| 完成交付率 | Delivered Order ÷ Paid Order |
| 接受率 | Accepted Order ÷ Paid Order |
| 退款率 | Refunded Order ÷ Paid Order |
| 7/30 日复购率 | 窗口内再次付费用户 ÷ 已到达该观察窗口的首次付费用户 |

融资会谈中使用过的 `2%` 只能放在“待验证假设”列；本轮结束后必须由上述两个明确口径中的一个替换，不能继续模糊使用“转化率”。

## 6. 60 秒 Wow Moment

目标不是做炫技动画，而是让用户和投资人在一分钟内看见“为什么这不是普通 Chat”。

### 0–10 秒：输入真实任务

- 上传一张作品；
- 选择用途与目标受众；
- 可选一张参考图；
- 页面明确显示由哪位创作者的方法驱动。

### 10–20 秒：展示任务理解

- 用一句话复述用户目标；
- 显示将使用的诊断维度；
- 说明不会访问哪些无关数据。

### 20–45 秒：出现专业差异

- 对作品做可视化标注；
- 给出三个按优先级排序的问题；
- 每个问题说明“为什么”与“怎么改”；
- 避免泛化的“构图更好、颜色更协调”等空话。

### 45–60 秒：交付可行动结果

- 展示 Before/After 改版预览或标注对比；
- 给出可复制的修改 Prompt、参数或步骤；
- 提供“继续自己改 / 再跑一次 / 升级真人服务”的明确下一步。

### Wow Moment 验证

同一输入至少运行两套结果：

1. 通用免费 AI 基线；
2. Combo 的创作者方法版本。

由目标用户和创作者按预登记 rubric 盲评：问题识别准确性、建议可执行性、风格匹配、结果改善和购买意愿。不能只展示团队挑选的成功案例；失败和无差异案例同样归档。

## 8. 平台跃迁前置指标

首轮成功只证明创作者变现工具的一个垂类可能成立，不证明平台成立。以下指标只做观察，不作为本轮美化故事的素材：

| 平台前置信号 | 定义 | 为什么重要 |
|---|---|---|
| 跨创作者购买率 | 买过第二位不同创作者的用户 ÷ 已到观察窗付费用户 | 证明用户关系不只属于单个 KOL |
| Combo 内生需求占比 | 非创作者外链带来的实收 GMV ÷ 总实收 GMV | 证明平台开始提供创作者自己没有的需求 |
| Context 复用率 | 经用户明确授权，在第二个任务复用 Context 的用户占比 | 证明跨服务状态有真实便利，而非数据锁定 |
| 路由增益 | 使用 Combo 匹配后，相对人工/随机选择的完成、退款或满意度提升 | 证明路由层创造结果价值 |
| 跨任务复购 | 用户从单次诊断进入下一视觉任务的真实付费 | 证明需求不是一次性尝鲜 |
| 创作者二次发布率 | 上线第二个产品或主动更新的创作者占比 | 证明供给侧形成持续经营 |

只有当跨创作者消费、平台内生需求和结果路由至少开始出现真实订单证据后，才讨论 Marketplace、Feed 或“人类专业能力交易与路由网络”。

## 9. 实验有效性门槛

在判断继续或停止前，本轮必须满足：

- 至少 3 位创作者真实上线，而不是只完成 Demo；
- 每位创作者完成一次可追踪的真实渠道发布；
- 支付、交付、Runtime 成本和退款事件全部可核对；
- 免费、折扣、平台补贴和自然现金订单分开统计；
- 至少保留一个未经过团队挑选的连续订单样本；
- 所有创作者使用同一漏斗定义和成本口径。

若不满足这些条件，只能结论为“实验无效或样本不足”，不能得出方向成立/不成立。

## 10. 继续、停止与转向门槛

### 继续扩大同一垂类

同时满足以下条件，才把样本从 3–5 位扩大：

- 至少 3 位创作者完成真实上线；
- 真实付费不只来自一位异常强创作者，至少两位创作者产生现金订单；
- 代表性订单在完整成本口径下贡献为正；
- 用户盲评能说清 Combo 版本相对通用 AI 的具体差异；
- 退款和人工补交付未突破预登记上限；
- 至少出现自然复购、下一次任务请求或明确的重复使用信号；
- 创作者认为净收入与投入有意义，并愿意继续发布或更新。

这仍只允许扩大“AI 原生专业视觉创作者”垂类，不允许直接扩到交易、占卜或泛咨询。

### 停止当前任务

出现任一硬条件即停止扩量：

- 在满足有效曝光条件后，全体创作者仍没有真实现金订单；
- 付费只在全额补贴、熟人支持或团队代购下出现；
- 调整一次定价或任务边界后，单任务贡献仍为负；
- 通用免费 AI 在盲评中与创作者版本无可解释差异；
- 每单持续需要创作者亲自重做，无法形成可规模化第一层服务；
- 退款、版权、隐私或安全风险超过预登记边界；
- 多位创作者明确表示收入不足以支持继续投入。

### 转向但保留垂类

如果用户需要该服务，但 AI 自动交付不成立，可转为：

- AI 免费/低价诊断，真人付费升级；
- 创作者内部提效工具，而非粉丝侧收费产品；
- 预约、筛选和交付管理工具；
- 高客单定制服务的线索入口。

转向后的收入和人工成本必须重新建模，不能继续沿用“自动 AI 产品”的毛利假设。

## 11. 证据记录规范

### 11.1 每项结论都要有 Evidence ID

```yaml
evidence_id: "CV-[creator]-[date]-[sequence]"
```
