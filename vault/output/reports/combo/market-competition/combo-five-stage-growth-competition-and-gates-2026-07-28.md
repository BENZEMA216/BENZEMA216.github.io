# Combo 五阶段增长、竞争与验证闸门

> Combo 当前从 KOL Agent 变现切入；每一阶段不是自然升级，而是必须证明一项新的控制权。专业服务“美团”和目标托管网络均为条件式期权。

## 一句话故事

Combo 先帮助垂类 KOL 把反复提供的专业服务变成可收费、可规模化交付的 Agent；再用真实结果、统一履约和跨供给复购，把 KOL 的首单信任逐步转成 Combo 的平台信任；只有这些证据成立，才继续扩张为专业服务交易网络和可被超级 Agent 调用的组合履约网络。

飞书工作稿：[Combo：从 KOL Agent 变现到 Agent 网络](https://zcndjgnt0026.feishu.cn/docx/FVgIdbDJhoNTDtxHi4qc1fDNnke)

## KOL 获取：30 天联合发行试点

优先找尚未被满足的重复需求，而不是粉丝最多的人：过去确有高密度私信、点评或人工付费；结果能被压缩成一个 SKU；个人方法会影响质量；失败可发现、可返工；本人愿意持续纠正。第一次沟通可以带一个基于公开材料制作、仅供私下讨论的结果原型，未经授权不得发布或投放。

30 天只验证一个“KOL × 一个结果 SKU × 一类受众”的首单与履约，不证明平台、复购或信任已经转移。退款、续购、Combo 直接召回和跨供给购买继续追踪到 D60/D90。

试点必须预先锁定：

- KOL 提交的需求证据、最小材料、审核工时和两次独立可追踪的自然流量发布；
- Combo 只交付一个 SKU、约定轮次修改，并登记创始人工时、现金成本、每单人工和停止上限；
- 联合品牌、人工咨询升级与蚕食保护；
- 关联、补贴、折扣、付费投流和自然现金订单的独立 cohort；
- 姓名、形象、内容、私有材料、方法、营销背书和训练用途的分别授权，以及退出后的材料、订单和结果记录处理。

未完成约定发布，只能判供给实验无效；每单依赖团队重写或每位 KOL 都要求专属功能，判为代运营；如果 KOL 用通用 Agent 工具能以更少成本得到相同结果，判 Combo 没有产品价值。

供给侧成功不是签约、上线或发一次链接，而是 KOL 在相同分成、无新增补贴、结果与失败数据全部披露后，仍愿意续约并提供新的有效流量。若支付共创费或保底，必须单列为 KOL CAC，相关订单和续约不能用于证明自然需求或供给留存。

## 供给复制：复制的是结果品类

“同垂类 3–5 个 KOL”不是严格复制单位：同属 AI 视觉创作，但分别出售品牌咨询、提示词和改图，仍是三套业务。真正可复制的是同一结果品类、同一 SKU 族：buyer job、输入结构、交付物、验收、异常处理和成本结构相同，KOL 的方法、案例、风格、品牌与禁区是受控差异。

锚点 KOL 只负责发现模板。后续证据按四步递进：

1. KOL2：独立关系和受众、标准分成、无保底，不新增产品原语或核心代码。
2. KOL3：非创始团队按同一 SOP 完成上线和首个满意订单。
3. KOL5：至少一位来自非创始来源，并走完“合格 → 上线 → D90 活跃”。
4. 扩张：全成本上线和首个满意订单继续加快，同时首稿接受、退款、人工升级、KOL 审核时间、贡献毛利和自然续约不恶化。

每个 SKU 按售价和目标贡献毛利反推模型、支付、KOL 分成、人工分钟、获客与上线成本上限；按获取来源、onboarding 方式、产品版本和订单来源分 cohort，并记录所有失败者。转介绍只有产生第二代“合格 → 上线 → D90 活跃”才算渠道，不能因签约或曝光直接称为飞轮。

如果多数新 KOL 仍要重做 SKU、流程或核心代码，创始人工时或运营人数随供给线性增长，或渠道只有签约没有 D90 活跃，就停止平台叙事，把业务按代运营或单一垂直结果公司重估。

## 分发：当前还没有飞轮

KOL 私域是首单渠道，不是护城河。Combo 当前要验证的不是“更多 KOL 带来更多 GMV”，而是一次满意履约能否生成不再依赖原 KOL 的下一笔付费需求。KOL 转介绍属于供给获取；同一 KOL 的相邻 SKU 属于留存和客单扩张，都不能拿来证明消费者分发。

需要依次证明四层：

| 层级 | 具体链路 | 成立 Gate |
|---|---|---|
| 可预测渠道 | KOL 自然内容/私域 → 专属深链 → 付费 → 结果验收 | 多个独立 KOL 至少两次自然发布后，全成本消费者 CAC、回收期和单笔贡献仍可预测 |
| 成果传播循环 | 满意订单 → 安全脱敏与用户授权 → 自然分享 → 新用户付费 → 新的满意订单 | 至少两个独立 cohort 连续闭环；贡献为正，退款和人工分钟不恶化 |
| Combo 自有需求 | Combo 内容、搜索或推荐 → 用户购买陌生供给 | 没有原 KOL 再次发布或背书，仍产生可回收 CAC 的真实订单 |
| 分发飞轮 | 历史订单和用户基数增加 → 非 KOL 触发订单增加 → 新订单继续产生分发资产 | 非 KOL 触发净订单占比持续上升、边际 CAC 下降、贡献为正，质量与履约成本稳定 |

KOL 自然深链、投流、激励分享、自然分享、Combo 自有入口、站内推荐、关联与补贴订单必须分 cohort。新客订单贡献为：

`实收 − 退款 − KOL 分成 − 模型/工具 − 支付费 − 直接履约/客服 − 渠道激励`

保底与招募、上线工时进入创作者 CAC；投放、内容制作和可归因分发运营进入消费者 CAC。样本足够后用 holdout 或错峰发布检验增量，不能把归因链接直接当因果。

并非所有 SKU 都适合成果传播。若安全脱敏后仍愿意公开的订单比例过低，就删除成果卡飞轮假设，改走复购、渠道嵌入或自有需求，不用 AI 内容填充 Feed。

第二次自然发布普遍失速、成果卡只有点击没有付费、D90 后订单仍几乎全部依赖原 KOL/新增 KOL/投流/更多运营人力，或非 KOL 触发订单占比和边际 CAC 没有改善时，应停止讲消费者平台和分发飞轮。

## 留存：两套待验证的经济行为

Combo 尚未证明留存。Context、订单历史和 Agent 联系人只是机制；只有它们改变了下一次付费或持续经营，才构成价值。

| 一侧 | 真正的留存 | 不能算作留存 |
|---|---|---|
| 消费者 | 在预登记的下一次合格需求窗口内，没有原 KOL 再次触达或激励，用户再次付费；购买陌生供给且单笔贡献为正，是平台留存的最强证据 | 原订单修改、分期交付、KOL 再次发帖带回、同一 KOL 的 cross-sell、收藏或保存联系人 |
| 供给者 | 在标准条款、无新增补贴下，继续接单、维护版本与 SLA；原 SKU 保住 GRR，第二个独立结果 SKU 带来正 NRR 和净增收入 | Agent 仍上架、合同未到期、保底或独家锁定、创始人持续代运营、只靠本人反复推广 |

不同 SKU 必须预登记自然复购周期，只统计已经进入下一次合格需求窗口的成熟 cohort，并按 KOL、获客来源、是否补贴和合同条款拆分。低频品类不能用尚未到来的 LTV 掩盖首单亏损；首单经济必须独立成立。

Context 的价值必须和匹配的冷启动 cohort 对照：是否减少填表、澄清和人工分钟，缩短交付，提高首稿接受率或降低退款。Agent 联系人也只有在发起下一项真实任务并减少重新选择时才有价值。若关闭 Context 后结果、时间和成本没有显著差异，它只是存储，不是壁垒。

留存订单贡献为：

`实收 − 分成 − 推理/工具 − 支付 − 质检/客服 − 退款 − 召回成本`

供给者净收益还必须扣除本人审核时间、声誉风险和渠道蚕食。原 SKU 的 GRR 与包含第二 SKU 的 NRR 要同时报告，不能用新品收入掩盖旧品衰退。

应停止留存叙事的信号包括：去掉 KOL 转发、优惠和人工召回后复购消失；Context 没有因果增益；D60/D90 供给留存依赖保底或代运营；人工分钟不降且质量恶化；复购和 GMV 长期集中于首个 KOL。

## Context 与信任转移：四项独立 Gate

**裁判：重写。** 一次满意结果更可能先强化原 KOL，而不是自然把信任交给 Combo。结果质量、平台履约保障、平台选择供给和目标委托是四种风险等级不同的信任，前一项成立不能证明后一项。阶段二只验证用户是否信任 Combo 的交付、补救与推荐，不提前讲目标委托。

Context 也不是一个对象，更不是天然护城河：

| 记录 | 控制边界 | 只有何时才成为 Combo 的价值 |
|---|---|---|
| 用户输入与项目档案 | 用户可纠错、逐项授权、导出和删除；跨供给默认不共享 | 经用户确认后复用，因果改善下一次成本、速度或结果 |
| 供给者方法与 IP | 按 SKU、用途、期限和训练权分别授权，可撤回 | 授权持续存在，并带来相对通用模型的稳定结果增益 |
| 平台观察到的 Run 数据 | 只保留获授权、可追溯的版本、修改、接受、退款与工具轨迹 | 标准化后能改善某类 Context 下的质量、路由或人工成本 |
| 责任与结算账本 | Combo 保留履约所需的最小授权、执行、审批、退款、升级和分账记录 | 持续降低争议、保障损失、人工和脱媒，而不是制造数据锁定 |

四项实验按 SKU 预登记合格人群、唯一主指标、观察窗口、最小有意义差异和停止规则，不设全平台统一假数字：

| 实验 | 对照 | 成立 Gate |
|---|---|---|
| Context 因果价值 | 同一模型和界面下，“读取用户确认的历史 Context”对比“只读当前请求” | 少填材料、少澄清或少人工，或首稿接受、交付时间、退款显著改善；增益覆盖存储、安全与权限成本 |
| 双品牌与直接回访 | 同一 KOL、SKU、价格和流量下，KOL 单品牌对比“KOL 方法授权 + Combo 交付与售后” | 转化损失在预登记容忍范围内，同时出现无提示记住 Combo、脱离 KOL 链接的主动回访 |
| 透明跨供给推荐 | 用户已出现真实第二需求时，Combo 给出身份可见、理由和共享字段清楚的推荐，对比同候选集合自主选择 | 无原 KOL 背书或优惠的未退款跨供给付费增加，质量不降，扣除推荐、保障与售后后贡献为正 |
| 售后恢复 | 对自然发生、严重度匹配的失败订单，Combo 统一重做、换供给或退款，对比原供给处理 | 以相同或更低恢复成本提高解决率，并带来后续直接回访或购买 |

隐去 KOL 后盲测结果更好，只证明结果质量；接受免费推荐，只证明点击意愿；双品牌不伤转化，只证明 Combo 标识无害；赔偿后复购若来自补偿套利，也不证明信任。

以下任一长期成立，都应停止相应叙事：Context 开关没有因果增益，则删除 `Context moat`；用户只愿同 KOL 复用、不愿跨供给，则停止讲 Context 网络；Combo 路由不优于自主选择或通用模型，则停止讲选供给能力；责任账本不降低退款、争议或保障成本，则 Combo 只是交易记录工具；高风险任务始终要求指定真人，则不讲普适目标托管。

## 竞争：不是一个完整对手，而是被分层截走

中国大厂最可能分别拿走 Combo 的一层：

- 抖音/小红书拿发现与首单，也已有原生小程序、服务交易、订单与售后接口。
- 微信拿关系、复访与默认需求入口；腾讯元器可把公众号内容变成 Agent 并发布到微信渠道。
- 阿里/支付宝拿默认意图、订单历史、商家供给、Agent 授权支付和基础售后。
- 美团拿本地服务密度、时空库存、调度、评价、验真与争议治理。
- 扣子、腾讯 ADP 及模型厂商把 Agent 创建、Runtime、记忆和工具调用免费化。

海外同样分层：

- Meta/YouTube 掌握创作者关系与内容发现。
- Microsoft/LinkedIn 掌握职业身份、组织 Context 与企业工作入口。
- Fiverr/Upwork 已拥有专业供给、服务 SKU、合同、评价、支付、交付和争议处理。
- Shopify 更可能成为商业基础设施合作方。
- OpenAI/Google 等超级 Agent 长期可能拥有用户意图、默认路由与对话内交易。

因此 Combo 最危险的失败形态，不是被另一个 Combo 击败，而是退化为一个没有用户关系、交易数据与履约权的 Agent 制作工具。

### 模型厂商裁决：重写为控制点竞争

**已知事实**：OpenAI、Google、Anthropic 已经把 Agent 创建、Memory、工具、Runtime、评测和目录分发做成平台能力；ChatGPT 还把应用发现与结账带入对话。具体产品形态并不稳定——OpenAI 已宣布停止 Agent Builder 与原 Evals 产品——因此不能再用“Builder → Store”推演固定路线，也不能把创建器、通用记忆、多模型路由或 Prompt 当壁垒。现有官方证据尚不能证明模型厂商会承担专业服务的真人授权、验收、补救、退款和供给结算。

**当前选择**：不和模型厂商争“大脑”，把它们同时当生产资料和分发渠道。用户在 ChatGPT、Gemini 或微信里提出“按目标 JD 重写简历”时，通用模型可以直接起草；只有当用户购买一个有价格、SLA、验收与退款保障的结果时，入口才需要调用 Combo。Combo 可以失去前台，但不能失去订单与履约身份。

| 租用 | 必须控制 | 验证 Gate |
|---|---|---|
| 基础模型、通用推理、工具调用、Runtime、通用 Memory 与入口流量 | 真人商业授权与退出；结果 SKU；Gold Set 与质量版本；订单、QA、真人升级、退款、备用供给、责任与结算账本 | 同 SKU 的模型替换盲测与故障切换；“裸模型”对照 Combo 履约；KOL 深链、自有入口、外部模型入口分别核算增量订单与贡献毛利 |

**停止条件**：若通用/原生 Agent 在核心 SKU 上达到相同结果且用户不再付费；KOL 在原生平台能以更低成本获得同等净收入与售后；平台抽成后无法覆盖履约责任；或单一模型/入口决定大部分生存能力且订单、授权和质量资产不可迁移，就停止讲独立的人类能力网络，收缩为垂直履约商或结束该 SKU。

**远期 Bet**：不是“模型永远替代不了专家”，而是选定 SKU 中，经授权的真人方法与 Combo 的履约机制仍能持续产生可测的质量、付费或成本优势；模型账户即使拥有默认需求入口，仍需要可授权、可验收、可补救、可结算的外部专业供给。

### 抖音、小红书、微信裁决：接受前台外置，检验履约增量

**已知事实**：抖音不只有流量，服务市场已有服务搜索、定价、支付、交付确认与按转化/接单/实施表现排序，小程序内容挂载又明确限制外部交易导流；小红书交易组件已把商品、订单、售后与结算同步接入笔记、直播和主页等原生场景；腾讯元器可导入公众号文章生成 Agent，发布到公众号、客服、企业微信等渠道，并以白名单方式测试微信支付 MCP。三家都已占据 Combo 所需闭环的一部分，不应再被统称为“外部获客面”。官方证据尚未证明它们已经完成跨 KOL 的专业结果合约、多供给 QA、替换、退款责任与贡献结算。

**当前选择**：不复制抖音/小红书 Feed，也不重做微信联系人。KOL 可在原平台发布，消费者可在原生小程序结账、在微信继续项目，甚至从不打开 Combo；Combo 只有在后台持续控制真人授权、结果合约、任务级 Context、质量版本、QA、补救和责任账本，并能跨渠道迁移时才成立。支付轨道可以属于平台，但订单与结算事件必须可审计、可导出。

| 原生基线实验 | 渠道独立 Gate | 平台关系 Gate | 停止条件 |
|---|---|---|---|
| 同 KOL、同 SKU、同材料、同内容与价格，对照原生 Agent / 小程序与 Combo；比较付费转化、首稿接受、退款、KOL 净收入、上线与每单人工 | 同一 SKU 至少在两个独立渠道产生正贡献订单；按抖音短窗口、小红书搜索窗口、微信复访窗口分别计入内容、运营、平台与支付成本 | 暂停原 KOL 和原平台再次触达后，成熟用户仍直接回到 Combo 项目/订单，或无背书购买陌生供给且贡献为正 | 原生链路以更低成本达到同等结果与售后；Combo 拿不到必要订单/退款/授权事件；D90 GMV 仍随新增内容和运营线性增长 |

平台 OAuth、小程序开发和交易授权不能替代 KOL 对姓名、形象、内容、方法、训练、修改、收益分配与退出的商业授权；两类合同必须分开。

**竞争假设**：抖音可能把评论、私信与推荐直接连接到创作者 Agent；小红书可能增加服务 SKU 与“应用到我”；微信可能成为个人 Agent 的默认关系入口。这些都不能写成既成事实，但足以要求 Combo 从第一天保持多渠道、模型无关和履约记录可迁移。

### 阿里/支付宝与美团裁决：租用轨道，保有结果责任

**已知事实**：千问已经连接淘宝商品发现、比较、下单、订单、物流与售后，并整合淘宝闪购、支付宝、飞猪和高德；支付宝已把订阅、按量计费、Agent 授权支付、履约回执与退款做成基础设施。美团已经把消费者 AI、商家 AI、真实订单、评价、验真和争议治理叠加到本地生活网络。这些事实证明通用交易与本地履约轨道正在 Agent-native 化，但尚未证明两者已经完成真人方法授权、非标准专业结果验收和跨供给责任结算。

**当前选择**：支付、订单、发票、基础退款和现实执行轨道可以租用；结果责任不能让渡。用户可以在千问里购买“按目标 JD 重写简历”，支付与订单留在支付宝或淘宝；Combo 必须仍是商户或履约责任方，控制真人授权、结果合约、任务级 Context、供给准入、Gold Set、路由、QA、替换、真人升级、结果证据、退款原因与供给结算。若版本化 SKU、订单、授权、验收、退款与结算事件不可审计和导出，只把该平台当获客渠道。

“专业服务美团”只是一项条件式运营类比，不是“专业服务天然具备美团密度”的事实。首个需求单元应固定为：

`同一人群 × 同一 Buyer Job × 同一输入 × 同一交付物 × 同一风险 × 同一 SLA / 价格带`

| 阶段三 Gate | 停止条件 |
|---|---|
| 同一单元至少有一位主供给、一位无需用户重填 Context 即可接管的备用供给和一位独立 challenger；三者通过同一 Gold Set；替换不破 SLA；路由相对用户自选或轮询改善完成率、退款或成本；`实收 − 平台费/投流 − 供给分成 − 模型/工具 − 支付 − QA/客服 − 退款 − 备用容量 − 集成` 为正 | 原生平台达到同等结果且成本更低或供给净收入更高；不存在可替代密度；路由无增益；争议与人工吞掉贡献；关键交易事件不可导出；Combo 只生成结果或转发 API，无法承担履约责任 |

**竞争假设与远期 Bet**：阿里可能把真人服务 SKU 纳入千问采购，美团可能从相邻本地服务扩展到远程专业结果；这不是既成事实。若上述 Gate 通过，两者可以成为 Combo 的入口、商业轨道或现实执行 Skill；若不通过，Combo 应停在垂直托管服务，而不是继续放大“专业服务美团”。

## 必须争取的控制点

Combo 可以不拥有模型，也可以不拥有第一次触达，但不能丢掉这本账：谁授权了什么能力、卖了什么结果、在什么 Context 下由谁交付、结果怎样、失败谁负责、收入如何分配。

对应六个控制点：

1. 可验证、可撤回、可结算的真人商业授权。
2. 有输入、边界、交付物、时限、验收和补救的结果契约。
3. 质量控制、返工、退款、真人升级与备用供给。
4. “用户 Context—任务—供给—结果”的情境化信誉。
5. 供给收入与 Agent 改进闭环。
6. 多真人/Agent 的贡献、责任、分账和跨平台可调用性。

授权、QA、退款和结算本身只是基础设施。只有它们持续转化为稳定供给权、更低退款率、更少真人分钟、更高接受率、更优跨供给匹配与复购，才成为可复利资产。

## 条件式路线

五阶段不是承诺：

- 如果付费结果与正贡献不成立，停止扩张。
- 如果供给不能模板化复制，接受它是代运营或单垂类产品，不讲平台。
- 如果平台自产需求和第二供给购买不成立，停在 KOL 经营系统。
- 如果统一路由与履约不能改善完成率和毛利，停在垂直结果公司。
- 如果用户不愿授权目标，或组合交付不赚钱，不进入目标托管。

阶段三和阶段四是上行期权；KOL 经营系统或垂直结果公司也可以是独立成立的终点。
