# Combo 当前公司叙事

> 截至 2026-07-17，本文件是 Combo 当前公司定义与对外表达的唯一真源。若旧 Agora 文档与本文件冲突，以本文件为准。
>
> **边界：Combo 是当前公司与产品；Agora 是长期平台机制与历史研究代号。保留 Agora 研究，但不再用它代表公司现状。**

## 0. 核心判断

Combo 当前不是 Agent Marketplace，也不能被表述为已经形成网络效应的平台。

Combo 当前是一款**带有平台期权的创作者变现工具**：先帮助一类垂直创作者把反复提供的专业服务产品化，借助创作者自己的内容、主页和私域完成第一轮分发，验证真实付费、交付质量和持续经营。只有在跨创作者消费、平台新增需求和 Context 驱动路由同时出现后，才进入平台叙事。

## 1. 三个标准版本

### 一句话

> **Combo 帮助垂类创作者，把反复提供的专业服务变成可收费、可规模化交付的 AI 产品。**

### 30 秒

大量垂类创作者有专业能力和粉丝信任，但现有变现方式各有缺口：咨询难以规模化，课程缺少个性化，社群运营重，广告也并不适合所有创作者。Combo 帮助创作者把历史内容、咨询记录和工作方法，整理成一个有明确输入、输出、价格和服务边界的 AI 产品；创作者把产品链接放进自己的内容、主页或私域，用户为一个具体结果付费。现阶段我们要证明的不是 Marketplace，而是创作者能否更快上线产品、获得真实增量收入，并愿意持续发布第二个产品。

### 2 分钟

今天很多垂类创作者每天都在重复回答相似问题、提供相似判断，但这些服务要么依赖本人时间，要么只能被做成缺少个性化的课程和社群。Combo 的切入点不是复制一个“KOL 本人”，而是把其中**可重复、可审核、可交付**的第一层专业服务做成 AI 产品。

创作者可以从历史内容、私信问答、直播、课程、咨询记录、文档或已有 Agent Session 中导入材料。Combo 协助提取方法、定义输入输出和服务边界，由创作者审核后，再接入 Runtime、权限化 Context、计量、支付和结果交付。复杂或高风险需求仍然升级给真人；AI 产品负责低价、可规模化的第一层服务。

第一阶段的分发不是让用户进入 Combo 浏览 Agent，而是：

```text
创作者的内容 / 主页 / 私域
  → 一个具体 AI 产品
  → 用户为明确结果付费
  → 创作者获得增量收入
  → Combo 从真实成交中获得收入
```

这条链路成立后，Combo 才有资格讨论平台：当同一用户开始复用自己的 Context、购买多个创作者的产品，Combo 能给创作者带来其自己没有的新增需求，并利用结果与评价数据改善能力路由时，Combo 才会从创作者变现工具升级为人类专业能力的交易与路由网络。

## 2. 客户与角色

| 角色 | 当前定义 | Combo 为其解决什么 | 当前不能假设什么 |
|---|---|---|---|
| 垂类创作者 | 当前首要客户、供给者和第一分发者 | 把重复专业服务做成可售卖 AI 产品，降低单位交付时间，增加收入形态 | 不能假设所有 KOL 都需要增量收入，或都愿意交付 Context |
| 粉丝 / 终端用户 | AI 产品的使用者和付款者 | 以低于真人服务的价格，获得一个清楚、个性化、可交付的结果 | 不能假设“信任 KOL”自然等于付费和复购 |
| Combo | 产品化、运行和交易基础设施 | 能力提取、产品封装、Runtime、权限、计量、支付、交付、退款与经营数据 | 不能把技术链路存在等同于商业闭环成立 |
| 创作者合作方 | 可提供种子供给、内容资源或分发协作 | 帮助形成首批真实产品与实验样本 | 合作意向不等于已上线、已成交或已复购 |

最适合首轮验证的创作者，通常同时满足：已经反复提供某项服务；有明确方法；结果可以半结构化；用户愿意为结果付费；错误风险可控；真人供给受时间限制。它是筛选假设，尚未被规模化验证。

## 3. 真实问题

Combo 当前要解决的不是“世界上缺少 Agent”，而是：

> **创作者已经在反复提供专业服务，但现有方式难以同时做到个性化、规模化和可持续收费。**

具体表现为：

- 咨询依赖本人时间，供给上限低；
- 课程和数字内容可以复制，但难以根据每位用户的 Context 给出结果；
- 社群需要持续重运营；
- 广告和带货依赖体量，也可能损耗用户信任；
- 大量重复私信已经构成需求信号，却没有被产品化；
- 通用模型能提供平均答案，但创作者是否能稳定提供明显更好的结果，仍需逐场景证明。

这些结论目前主要来自融资会谈、团队经验与产品假设，不是大样本用户研究结论。每个首发垂类仍需用真实成交和结果质量单独验证。

## 4. 产品机制

Combo 的目标闭环是：

```text
创作者材料与工作轨迹
  → 提取可重复的方法和判断规则
  → 创作者审核能力边界与示例
  → 封装为有明确输入、输出、价格的 AI 产品
  → 绑定 Runtime、权限化 Context、计量与支付
  → 向用户交付结果，记录完成、退款与评价
  → 反哺产品迭代和创作者经营
```

| 机制层 | 当前对外表达 | 证据边界 |
|---|---|---|
| 能力导入 | 支持从内容、文档、问答、咨询记录和 Agent Session 等材料中提取方法 | 已有工程链路与演示基础；不同材料的稳定提取质量仍需验收 |
| 创作者审核 | 创作者决定哪些方法可发布、哪些 Context 可使用、何时升级真人 | 是必须坚持的产品原则；尚需用真实创作者工作流验证易用性 |
| AI 产品封装 | 把方法变成明确的输入、输出、边界、案例和价格，而不是只上传 Prompt | 产品机制明确；上线时长和成功发布率尚无真实基线 |
| Runtime 与权限 | 负责模型调用、工具、权限和用户 Context 的安全执行 | 是后台基础设施，不作为当前前台定位或已形成壁垒的证明 |
| 交易与交付 | 支付、计量、结果交付、退款、结算和经营数据 | 是商业闭环必需项；真实支付、退款和贡献毛利尚待验证 |
| 结果评价 | 记录什么用户、什么任务、什么版本下得到什么结果 | 当前先服务单产品迭代；跨创作者路由属于远期假设 |

`Skill`、`Agent Capability Package`、`Context Network` 都可以继续作为内部机制语言，但不应取代“创作者增量变现”成为当前对外问题定义。

## 5. 分发路径

当前首要路径是**创作者自带需求与信任，Combo 承接产品化和交易**：

```text
创作者内容 / 主页 / 直播 / 私域
  → 单一服务链接
  → 单一结果承诺
  → 单一价格
  → 支付与交付
  → 满意、退款、复购或升级真人
```

这意味着：

- 消费者不需要先记住 Combo，也不需要在平台 Feed 中“捞 Agent”；
- KOL 信任可以降低首次获客成本，但不是产品价值和留存的替代品；
- 第一阶段不以 Agent 数量、上架量或浏览量证明增长；
- 先看每位创作者能否上线、卖出、获得收入，并继续发布第二个产品；
- Marketplace、Feed、算法推荐和补贴不是当前冷启动前提。

## 6. 当前商业模式

当前应使用“交易抽成”作为最简工作模型，而不是把多种收费方式一次讲全：

1. 创作者定义产品与价格；
2. 终端用户按次或按产品付费，具体形态以首轮实验为准；
3. Combo 提供产品化、运行、支付和交付基础设施；
4. 成交后支付创作者分成，Combo 保留平台收入；
5. 退款、推理、Sandbox、支付通道、补贴和支持成本都必须进入单任务经济模型。

会谈中出现过 **15% 抽成**，但它目前只是讨论口径，不是已验证或已最终确定的价格。下一版模型必须先定义抽成基数：是 GMV、扣除退款后的净 GMV，还是扣除模型与履约成本后的金额。

最低核算式应为：

```text
净 GMV = 支付金额 - 退款
平台收入 = 净 GMV × 实际抽成率
单任务贡献毛利 = 平台收入
               - 模型 / 推理成本
               - Sandbox / 工具成本
               - 支付费
               - 直接交付与支持成本
               - 单笔补贴
```

订阅、团队 License、定制服务和广告可以保留为后续选项，但当前不应分散对“是否有人愿意为一个明确结果付费”的验证。

## 7. 平台跃迁的三个必要条件

Combo 只有在以下三项同时出现后，才能从“有平台期权的工具”升级为“正在形成的平台”：

1. **跨创作者消费**：同一用户开始购买第二、第三个创作者的产品，并复用自己的 Context；
2. **平台新增需求**：Combo 开始给创作者带来其内容、主页和私域之外的真实付费用户；
3. **数据改善路由**：用户 Context、交易结果和评价数据，能够持续提高跨产品匹配、组合或交付成功率。

对应的证据不是 Agent 数量，而是：

- 购买第二个创作者产品的用户比例；
- 来自 Combo 推荐、而非创作者自有链接的 GMV 占比；
- 相似 Context 下的完成率、退款率和复购率是否因路由数据改善；
- 跨创作者组合是否创造了单个创作者无法独立完成的结果。

在这些数据出现前，`Marketplace`、`Feed`、`network effect`、`Context Network` 都只能标注为未来假设。

## 8. 证据状态

### 已确认

- 公司当前定义已经明确为“服务垂类创作者的变现工具”，而非面向大众的 Agent Marketplace；
- 当前第一分发路径是创作者内容、主页和私域，而非 Combo 公域 Feed；
- 团队已形成“材料 / Session → 能力提取 → Agent / 产品封装 → Runtime”的工程链路与产品架构；生产成熟度仍需单独验收；
- 融资整理会话覆盖心资本 WBJ、经纬 / Mario、江远资本、蓝色光标、星连资本、真格刘元，共整理 207 条问答。这证明反馈已被系统整理，不等同于市场验证；
- 多场会谈稳定指向同一缺口：真实上线、付费、完成、退款、复购与单位经济数据不足。

### 待验证

- 哪一个垂类最适合作为首发市场；
- 创作者是否愿意授权材料、审核结果并持续经营；
- 能力提取后是否稳定优于通用模型和临时 Prompt；
- 粉丝是否会点击、付费、满意并再次使用；
- 创作者是否获得相对课程、咨询、社群和广告的增量收入；
- 创作者是否愿意发布第二个产品；
- 价格、退款、推理成本、创作者分成和支持成本能否形成正贡献毛利；
- `Skill → Agent` 的技术链路能否形成难以替代的产品资产。

### 远期假设

- 用户会跨创作者复用 Context 并购买多个专业能力；
- Combo 能形成独立于创作者私域的需求入口；
- 结果数据会改善能力匹配、路由、组合、定价和声誉；
- Combo 最终可成为人类专业能力的交易与路由网络。

|---|---|---|
| “Combo 是 Agent Marketplace / 已经是平台” | 当前没有跨边交易与网络效应证据 | “Combo 是带有平台期权的创作者变现工具” |

| “偷数据”“灰色支付”“买号群发”“号被封”“笨笨用户”“兄弟情顶一顶” | 暴露合规、治理和专业度风险 | 使用“经授权导入”“合规支付路径”“受控渠道实验”“非 AI 原生用户”“已确认合作支持”等准确表述 |

## 11. 融资数字口径

### 基本规则

每个数字必须标记为以下一种，不能混用：

| 标签 | 含义 | 可用表达 |
|---|---|---|
| `actual` | 来自 Combo 已发生的产品或交易数据 | “截至某日，实际为……” |
| `prototype` | 工程或 Demo 已完成，但不代表商业使用 | “已实现 / 已演示，生产成熟度待验收” |
| `intent` | 创作者、合作方或投资人的意向 | “意向 / 在洽谈”，不能写“已拿下” |
| `benchmark` | 外部产品或行业数据 | 必须附来源，不转写成 Combo 自有数据 |
| `assumption` | 模型输入、类比或待测试参数 | “若……则……”，必须给公式与敏感性 |
| `future thesis` | 平台、网络效应和长期规模 | 只能作为条件式愿景，不写成预测事实 |

### 已知需要纠正的数字

- `300 × 8,000 = 2,400,000`，即 **240 万**，不是 24 万；它只代表理论触达基数，不能直接等同于用户或收入；
- `100,000 × 2% = 2,000`，不是四五千；2% 本身仍是 `assumption`；
- 2% 付费转化、10% 点击率、5,000 粉年增收 2 万、8,000 粉年增收 3 万，当前都属于类比或测算，不是 Combo 的 `actual`；
- 15% 抽成属于待测试的 `assumption`，且必须说明抽成基数；
- “十几个创作者”若尚未真实上线并成交，只能写成 `intent`；
- [agora-bp-agent-capability-package](/output/reports/agora/product/agora-bp-agent-capability-package/) 中的 `Seed $3M / stretch $5M` 属于 Agora 历史 BP 口径；在新的融资金额、估值、轮次和资金用途被创始人正式确认前，不得沿用为 Combo 当前 ask。

任何 GMV、收入、毛利或市场规模推导，都必须同时给出：样本范围、时间窗、漏斗基数、公式、币种、含税与否、退款口径、抽成基数和数据标签。

## 12. 当前验证门槛

下一轮融资表达不再以更多概念报告为核心，而以一个极窄闭环为核心：

- 一个垂类；
- 3–5 个真正上线的创作者产品；
- 每个产品只有一个明确结果和一个价格；
- 一个 60 秒内可理解的 Before / After Demo；
- 同一套漏斗：触达创作者 → 同意合作 → 成功上线 → 粉丝触达 → 点击 → 开始使用 → 付费 → 完成 → 退款 → 7/30 日复购 → 第二个产品发布；
