# Combo 正推与倒推：5–10 年用户场景与关键 Bet

> 查询：从今天“帮助创作者把重复专业服务做成收费 AI 产品”这件小事正推，Combo 五年、十年后可能长成什么；再从未来模型能力、算力基础设施和人的社会形态倒推，Combo 要占住什么位置？

> 状态边界：本文是 `future-thesis / scenario-planning`，不是预测、路线承诺或当前融资事实。当前公司定义仍以 [combo-current-story-2026-07](/output/reports/combo/narrative/combo-current-story-2026-07/) 为准。

## 摘要

正推最自然的路径不是“协同互联网”，而是：

```text
一个专家的结果 SKU
→ 一个专家经营多个 AI 服务
→ AI-native 专业实践的经营 OS
→ 跨专家的专业服务交易
→ 个人 Agent 采购专业升级
```

倒推则应使用最严苛假设：到 2036 年，通用模型在多数认知任务上达到专家水平，推理和编排接近商品化。届时仍可能稀缺的不是“会不会生成”，而是：

- 授权、账号、牌照和机构接入；
- 品牌、署名、品味和社会信任；
- 真实渠道、供应商和物理资源；
- 验收、质保、退款、保险与责任承担；
- 最新的私有现实反馈与可归因结果。

两种推演的交集是：

> **Combo 是 AI-native 专业实践的经营与交易系统：专家定义并拥有服务，模型承担越来越多执行，用户或其个人 Agent 购买有边界、可验收、可补救的专业结果。**

这不是命定终局。若专家版本不优于通用模型、用户不额外付费、创作者不持续经营、用户不跨专家购买，Combo 应停在 Creator SaaS，甚至停止该 SKU，而不是继续升维叙事。

## 一、今天这个“小事”到底是什么

当前原子交易不是 Agent、Skill、Prompt、模型调用或人机团队，而是：

```text
一位创作者已经反复提供某项服务
→ Combo 把输入、输出、边界、价格和升级真人条件定义清楚
→ AI 交付可审核的第一层结果
→ 用户真实付款
→ 创作者获得增量收入
→ 结果、退款、人工介入和复购被记录
```

当前首轮候选是 [AI 视觉作品诊断与改进包](/output/reports/combo/gtm/combo-one-vertical-validation-2026-07/)：

- 用户上传一张视觉作品、用途、目标受众和参考；
- 获得按创作者 rubric 完成的诊断、三个优先问题、修改动作和可视化预览；
- 复杂需求升级真人；
- 与同条件下的当前最强通用模型做盲测。

这个原子如果不能成立，后续所有平台、路由和个人 Agent 采购都没有起点。

## 二、正推与倒推回答的是两个不同问题

### 正推：今天已经拥有的东西会自然长出什么

正推只允许使用实际发生的相邻行为：

- 创作者发布第二个产品；
- 用户再次购买；
- 同一用户购买另一位创作者；
- Combo 带来创作者自己没有的需求；
- 结果数据真的改善下一单；
- 外部 Agent 开始调用这些服务。

它回答的是：

> 如果当前闭环成立，下一项最便宜、最自然的扩张是什么？

### 倒推：在最强未来假设下，什么仍值得付钱

倒推先假设：

- 通用模型已经很强；
- 模型会自动拆解任务和选择工具；
- 普通生成与分析接近免费；
- 个人 Agent 成为主要入口；
- 模型平台有能力整合支付、身份和分发。

然后问：

> 在这种世界里，用户为什么还要向 Combo 或某位专家支付一笔额外的钱？

两条线只有在交集处才值得长期下注。仅正推容易被当前产品限制想象；仅倒推则容易发明无法验证的基础设施。

## 三、决定终局的六个变量

### 变量 1：模型能力是统一还是长期分化

| 未来状态 | 含义 | 对 Combo 的影响 |
|---|---|---|
| 少数通用模型覆盖绝大多数任务 | 诊断、生成、拆解、路由和工具调用被系统层吸收 | Agent 编排与模型选择失去前台价值，Combo 必须靠专业服务的品牌、授权、交易和责任存活 |
| 多模型长期各有所长 | 视觉、行业、地域、私有部署和可靠性差异持续存在 | 模型选择和组合有短中期价值，但仍更像后台成本/质量优化，不应成为公司定义 |
| 通用模型很强但 Situated Context 仍重要 | 模型知道一般世界，却不知道用户当前状态、权限和历史结果 | Context、授权和真实履约数据可能改善服务，但只有形成 ground truth 才有网络价值 |

[harness-engineering](/wiki/maps/harness-engineering/) 已明确记录 `Harness assumptions expire`：今天必要的复杂编排可能被下一代模型直接吸收。因此 Combo 应把模型和编排视为可替换履约部件。

### 变量 2：算力趋近免费，还是高可靠算力仍然昂贵

| 未来状态 | 用户行为 | Combo 可能形态 |
|---|---|---|
| 普通推理和生成极便宜 | 用户先用个人 Agent 自己完成大多数任务 | Combo 只在低置信度、高风险、需背书或现实资源时出售“专业升级” |
| 高可靠、长 Context、视频或具身算力仍贵 | 用户不愿分别购买多种模型额度 | Combo 可以固定结果价格，通过缓存、批处理、蒸馏和混合 QA 控制成本 |
| 算力价格高度波动或区域分裂 | 企业更关心预算、数据驻留和可用性 | Combo 可能成为垂直 Managed Service，但成本路由本身不构成长期叙事 |

算力下降同时带来两种相反作用：

1. 降低 Combo 的履约成本；
2. 摧毁“卖一次普通生成”的价格。

因此模型越便宜，产品越必须从“给你一个回答”向“替你完成、验收、补救”移动。

### 变量 3：人的生产组织是分散还是重新集中

未来很可能不是“所有公司消失”，而是：

> **底层高度集中，边缘高度分散。**

- 少数公司控制基础模型、算力、操作系统、个人 Agent 和支付入口；
- 大量个人经营“专家品牌 + Agent 团队”的微型公司；
- 资本密集、强监管和长期协同领域继续由大型机构主导。

如果专家微型公司繁荣，Combo 更像 Practice OS；如果劳动重新集中到模型平台和大企业，Combo 必须转向企业采购、持牌机构或垂直 Managed Service。

### 变量 4：用户自己浏览，还是个人 Agent 代表用户采购

| 入口 | 产品要求 |
|---|---|
| 人浏览创作者内容和商品页 | 强 Demo、Before/After、人格信任、低摩擦支付 |
| 个人 Agent 采购 | 服务规格必须 machine-readable：输入、输出、价格、时限、限制、授权、验收和退款 |
| 企业采购系统调用 | 还需要供应商身份、预算、合规、审计、SLA 和稳定 API |

若个人 Agent 成为主要入口，Combo 的消费者 Feed 可能从未成为核心。用户甚至不会打开 Combo；Combo 更像专家服务商的 back office 和交易接口。

### 变量 5：AI 能否独立承担法律与商业责任

如果 AI 只能执行、不能签约、赔偿、承保或获得牌照，人或机构仍是责任主体；如果模型平台同时整合这些能力，Combo 的空间会大幅缩小。

因此“责任”不是宏大网络，而是非常具体的产品字段：

- 谁签约；
- 谁可以使用哪些数据和账号；
- 什么算完成；
- 谁审核；
- 失败时返工、退款还是赔偿；
- 哪些任务必须转给真人或持牌机构。

### 变量 6：AI 丰富后，人类身份是贬值还是升值

生成能力越丰富，可能越出现两种相反消费：

- 大量低风险任务完全去品牌化，只要便宜、快、好；
- 高品味、高身份和高后果任务出现真实性、署名与责任溢价。

Combo 要验证的不是“人类身份一定升值”，而是具体 SKU 中：

- 去掉创作者姓名后，盲测差异是否仍在；
- 相同结果加上专家署名、抽检和售后，付费是否提高；
- 用户究竟为结果、人格、内容周边还是责任出口买单。

## 四、正推：从 2026 到 2036 的条件式路径

| 时间 | 用户实际行为 | Combo 形态 | 升级 Gate |
|---|---|---|---|
| 现在—2 年 | 用户从创作者内容进入，购买一个明确结果 | 创作者变现工具 | 真实付费、盲测差异、低退款、人工可控、贡献毛利路径 |
| 2—5 年 | 同一专家发布多个 SKU，用户复购，AI 产品向真人高价服务导流 | AI-native Practice OS | 第二 SKU、持续更新、增量收入、用户留存 |
| 3—5 年 | 用户跨专家购买并复用项目 Context，Combo 带来新增需求 | 垂类专业服务交易平台 | 跨专家购买、平台内生 GMV、Context 确实降低 intake 或交付成本 |
| 5—10 年 | 个人 Agent 在低置信度、高风险或需要第三方资源时购买服务 | Agent 可采购的专业升级网络 | 第三方 Agent 发起订单，规格可读、权限可控、验收可执行 |
| 5—10 年以上 | 多个结果产品自然组成完整交付 | Managed Service Network | 多服务组合显著优于单模型，且统一承接仍有健康毛利 |

正推过程中，用户行为会把 Combo 分叉到不同公司：

| 实际行为 | 更可能的公司 |
|---|---|
| 用户主要为某位创作者名字付费 | 专家品牌授权与经营工具 |
| 用户主要为固定质量、速度和售后付费 | 垂直 Managed Service |
| 用户愿意跨创作者购买 | 专业服务交易平台 |
| 结果数据确实改善选择 | 路由网络 |
| 个人 Agent 大量调用 | Machine-purchasable service rail |
| 用户只尝鲜，不复购 | 创作者数字周边 / 活动工具 |
| 通用模型始终同样好且免费 | SKU 或方向被证伪 |

## 五、倒推：从 2036 年的强模型世界回来

假设 2036 年：

- 通用模型已经能完成大多数数字认知劳动；
- 用户拥有长期运行的个人 Agent；
- 任务拆解、多 Agent 组织和工具选择成为操作系统功能；
- 普通推理的边际成本很低；
- 模型平台掌握大量入口和 Integration。

用户仍可能为五种稀缺付钱：

### 1. 授权

模型“会做”不等于它被允许：

- 登录企业系统；
- 操作预算；
- 使用受版权保护的方法或素材；
- 代表持牌主体签字；
- 调用某个机构或个人拥有的资源。

### 2. 风险资本与责任

模型可以生成答案，但不自动等于有人愿意：

- 承诺 deadline；
- 返工；
- 退款；
- 质保；
- 承保；
- 对错误承担经济后果。

### 3. 稀缺现实资源

渠道、供应链、客户关系、场地、生产、拍摄、物流和本地执行无法仅由模型权重生成。

### 4. 人际合法性

谈判、审美背书、机构认可、某位专家署名和复杂利益协调，可能继续依赖特定人或组织。

### 5. 最新的私有结果

聊天记录和公开内容会快速贬值；“什么输入状态下采取了什么动作，最后是否成功、返工、退款或复购”更接近可用的 ground truth。[agentic-trajectory-data](/wiki/concepts/agentic-trajectory-data/) 已明确：缺少 outcome、feedback、lineage 和 consent 的日志不能形成可靠飞轮。

因此，2036 年仍可能成立的服务通常必须跨越某种现实边界：

> **取得权限、调动资源、改变外部系统状态、让某个主体署名，或者对失败承担后果。**

倒推到今天，Combo 应优先积累：

- provider 的真实身份、品牌与授权；
- 结构化结果合约；
- 交易和客户关系；
- 输入—动作—结果—返工/退款/复购证据；
- 真人升级和责任边界；
- 现实工具、渠道和资源连接。

不应把 Prompt、模型路由、通用 Agent 编排或原始 Context 数量当作十年资产。

## 六、四个边界世界

### 世界 A：便宜通用智能 + 分散专家经济

这是最值得下注的基准情景。

#### 五年

普通任务由个人 Agent 免费或低价完成。大量专家则经营一组有自己方法、品牌和售后的 AI 服务产品。用户只有在通用 Agent 置信度不足、需要正式背书或希望获得更稳定结果时，购买一次专业升级。

#### 十年

用户的 Agent 自动采购服务；Combo 主要服务专家侧，并向外部 Agent 暴露结构化服务规格、历史完成率、授权范围和补救机制。

#### Combo

AI-native Practice OS + 专业服务交易层。

#### 最大风险

通用模型平台原生提供专家身份、支付、退款、保险和分发；专家版本没有额外付费差异。

### 世界 B：多模型并存 + 分散微型公司

这是平台上限最高的世界。

#### 五年

不同模型在审美、行业、地域、语言、数据驻留和工具执行上长期分化。专家持续维护自己的 rubric、Eval、模型组合和例外处理。

#### 十年

个人 Agent 向多个专业服务请求报价，Combo 按真实任务和历史结果选择 provider、模型与工具。

#### Combo

专业服务经营系统 + 交易与结果路由网络。

#### 最大风险

Router、Workflow 和模型评测快速开源或基础设施化；用户仍不跨专家购买。

### 世界 C：通用模型 + Walled Garden

这是 Combo 最危险的世界。

#### 五年

少数超级 Agent 同时拥有用户入口、模型、支付、身份和创作者工具。用户在一个入口里完成大多数任务，专家只是平台内的一种背书或内容来源。

#### 十年

Combo 如果没有独立垂类供给、交易密度和现实履约能力，会被压缩为模型平台的一个插件，或直接消失。

#### Combo 的生存方式

- 占住一个平台不愿重运营的高价值垂直；
- 拥有独家或强关系 provider；
- 直接参与现实交付和责任；
- 成为跨模型平台可移植的专家业务后台。

#### 死亡信号

模型平台原生产品在同一任务上更好、更便宜，并同时提供身份、收费、售后和分发。

### 世界 D：高可靠算力仍贵 + 企业集中采购

这是更像 Managed Service 的现实路径。

#### 五年

用户不愿购买多个昂贵工具和额度，而以固定价格购买完整结果。Combo 使用便宜模型、昂贵模型、缓存、批处理和人工 QA 混合履约。

#### 十年

企业通过采购和 Agent 系统购买经过审核的外部专业服务，Combo 提供数据驻留、预算、合规、SLA、审计与供应商管理。

#### Combo

垂直专业服务零售商或 B2B Managed Service OS。

#### 最大风险

人工、返工、协调和上游算力吞掉毛利；它是一家 AI Agency，而不是可复利平台。

## 七、2031 年：三个具体用户场景

### 场景 1：专家经营一间数字 Practice

一位视觉创作者早上打开 Combo：

- 昨晚完成了 87 个付费诊断；
- 80 个自动交付；
- 5 个进入随机质量抽检；
- 2 个因置信度不足升级本人；
- 3 位用户购买了更高价真人改稿；
- 系统聚合出一种新失败类型，等待她更新 rubric。

她不再亲自完成 87 份任务，而是花一小时：

- 审核例外；
- 更新方法和边界；
- 处理高价值客户；
- 发布第二个结果 SKU；
- 查看收入、退款、人工时间和贡献毛利。

用户购买的是她经营的专业服务，不是她本人每一小时的劳动。Combo 的产品是 Practice OS，不是动态组织。

### 场景 2：普通用户购买“专业升级”

一位电商品牌主先让自己的通用 Agent 生成新品主视觉与详情页。Agent 可以完成大部分工作，但对品牌一致性和审美判断置信度不足，于是建议：

> 购买某位视觉专家的“新品上线前红队审查”，199 元。

用户授权本次读取素材。Combo 交付：

- 风险清单；
- 三处优先修改；
- 三个可直接使用的版本；
- 一次自动复核；
- 不合格时的重跑或真人升级。

他买的不是“专家 Agent”，而是一次用途明确、价格明确、可补救的专业升级。

### 场景 3：小企业由个人 Agent 采购多个结果

一家小品牌负责人对个人 Agent 说：

> “下个月去日本众筹，预算两万元，帮我准备一套本地化上市材料。”

个人 Agent 自己完成基础翻译和资料整理；在品牌语感、渠道适配和广告合规处调用三个外部服务：

- 视觉专家的品牌评审；
- 日本市场专家的渠道适配；
- 合规机构的广告检查。

用户只看到：

- 总预算；
- 交付计划；
- 数据权限；
- 三个需要本人决定的例外；
- 最终材料包。

所谓“动态组织”只是这三个服务在后台被顺序采购和组合，不是用户产品。

## 八、2036 年：用户可能根本不打开 Combo

一个可能的工作日：

1. 个人 Agent 发现用户公司的详情页转化率持续下降；
2. 它先用通用模型分析并修正显性问题；
3. 对品牌品味、当地监管或某项现实资源不确定；
4. 它向 Combo 查询三个外部专业结果产品；
5. Combo 返回来源、价格、范围、历史结果、所需权限和补救责任；
6. 用户只批准预算和敏感数据范围；
7. 服务完成后进行小流量测试；
8. 达到验收线后结算，失败则返工、退款或重新路由；
9. 专家获得方法授权与服务收入，只有异常案例进入其工作队列。

此时 Combo 可能像 Stripe 一样隐藏在主 Agent 与专业供给之间。它不是用户的总入口；它是：

> **供人类或个人 Agent 采购专业升级的经营与履约系统。**

必须同时保留反证：

> 通用模型能够可靠、低风险完成的任务不会调用 Combo。若模型平台也完整拥有授权、现实资源、责任和交易关系，Combo 的十年终局不成立。

## 九、人的社会形态：专家会变成什么

未来专家的职业身份可能从“简历上的职位”变成：

> **一个公开人格 + 一套持续更新的方法 + 一组代表他工作的 Agent + 一段可验证履约记录 + 一个责任主体。**

专业工作会被重新分成三层：

| 层 | 人的角色变化 |
|---|---|
| 执行 | 搜集、生成、分析、排版和常规沟通大量交给模型 |
| 判断 | 定义什么值得做、什么算好、复杂情境如何取舍 |
| 责任 | 授权、署名、承诺、处理异常和承担售后 |

这不意味着人人都会成为创业者。更可能同时存在：

- 依赖模型平台的一人公司；
- 大型企业内部的高杠杆小团队；
- 持牌机构与 AI 执行系统；
- 为专家提供品牌、版权、责任和经营服务的平台。

Combo 最适合服务的是“可被产品化的专业实践”，而不是抽象的全体人类能力。

## 十、Bet Stack：前一层成立，后一层才有意义

### Bet 1：专家差异存在

> 在一个有边界的任务上，专家方法持续优于同条件下最强通用模型。

证据：

- 预登记盲测；
- 去掉姓名后的偏好；
- 用户能指出具体差异；
- 模型升级后重复测试。

证伪：

- 多轮迭代后结果无稳定差异；
- 差异只来自名字和粉丝情绪，且不能产生复购。

### Bet 2：用户愿为差异与责任付费

> 用户愿意为更好的结果、固定范围、售后、背书或责任出口额外付费。

证据：

- 非熟人现金订单；
- 退款、使用和复购；
- 专家署名 / 抽检 / 售后的价格实验。

证伪：

- 只有免费使用和尝鲜；
- 用户直接回到通用模型；
- 首单是数字周边，之后没有需求。

### Bet 3：AI 产生真实经营杠杆

> AI 减少专家时间，而不是把成本转移到返工、客服和 QA。

证据：

- 每单人工分钟；
- 首次成功率；
- 完整成本贡献毛利；
- 订单增长时人工介入不线性增长。

证伪：

- 每单都需要专家重新完成；
- 毛利只有忽略售后和失败成本才成立。

### Bet 4：Practice 成立

> 创作者愿意持续经营，而不是只上线一次。

证据：

- 发布第二个产品；
- 主动更新方法；
- 收入复投；
- AI 服务为真人高价业务带来增量线索。

证伪：

- 大多数创作者依赖 Combo 团队持续代运营；
- 没有第二 SKU 或持续收入。

### Bet 5：消费者关系开始属于 Combo

> 用户愿意把后续任务和授权 Context 留在 Combo，而不只跟随单个创作者。

证据：

- 第二订单；
- 跨专家购买；
- Context 复用降低 intake、交付时间或退款。

证伪：

- 创作者私域长期贡献几乎全部订单；
- 首单后脱媒；
- 用户不接受 Combo 推荐另一位专家。

### Bet 6：交易数据形成路由价值

> Ground truth 使下一单更好，而不是只积累更多聊天。

证据：

- “输入状态—动作—结果—返工/退款/复购”闭环；
- 路由显著提高完成率或降低退款、交付时间；
- 数据有授权、lineage 和可比较任务。

证伪：

- 任务过于异质；
- Outcome 无法归因；
- 日志很多，但不改变任何指标。

### Bet 7：个人 Agent 成为新分发入口

> 外部 Agent 会采购第三方专业服务，而不是永远只调用自己的模型平台。

证据：

- 第三方 Agent / API 发起购买；
- 机器可读服务规格；
- 授权、付款、验收与退款可被代理执行。

证伪：

- 超级 Agent 把所有需求封闭在自己的 provider marketplace；
- 用户不允许 Agent 自动购买；
- 专家服务没有机器可验证的差异。

## 十一、现在应该积累什么，不应该提前建设什么

### 现在值得积累

1. 一个任务的清晰输入、输出、非承诺与验收标准；
2. 创作者的真实授权、rubric、正反例和版本；
3. 现金订单、退款、返工、人工时间和复购；
4. 用户 Context 的最小化授权与可撤回机制；
5. 同代最强通用模型的持续 baseline；
6. Provider 身份、责任边界和真人升级；
7. 从诊断逐步走向直接修改、部署、持续监测和有限责任。

### 不应提前建设

1. 横向 Agent Marketplace；
2. 复杂 multi-agent router 作为品牌核心；
3. 面向所有任务的动态组织工厂；
4. 没有真实跨店行为的 Feed；
5. 没有第三方调用需求的开放协议；
6. 把原始聊天、Context 数量或 Agent 数量称为数据网络效应。

## 十二、十条死亡路径

1. **认知商品化**：免费通用模型已经足够好。
2. **粉丝周边陷阱**：用户为人格尝鲜，但不为专业结果复购。
3. **薄封装陷阱**：模型平台原生提供 Creator Agent、支付和分发。
4. **Agency 陷阱**：每单人工、返工和协调吞掉毛利。
5. **好 SaaS、坏平台**：每个创作者独立获客，用户永不跨店。
6. **数据飞轮幻觉**：海量日志没有 ground truth，无法改善下一单。
7. **脱媒**：首单后买卖双方转向微信、私域或其他支付。
8. **巨头夹击**：模型入口与现有专业服务市场同时向中间收缩。
9. **责任事故**：赔偿、监管和保险成本超过品类利润。
10. **社会结构反向**：专业能力重新集中进大企业，个人 Practice 没有规模市场。

## 十三、最简洁的 5 年 / 10 年表达

### 今天

> **Combo 帮助垂类创作者，把反复提供的专业服务变成可收费、可规模化交付的 AI 产品。**

### 五年，条件式

> **Combo 成为 AI-native 专业实践的经营系统：一个专家可以用 AI 经营一间持续交付、持续更新的数字工作室。**

用户购买的是专家的视觉诊断、改稿、品牌审查或完整交付；专家管理的是产品、例外、质量、客户和收入。

### 十年，更强条件式

> **Combo 成为通用 Agent 与现实专业供给之间的可问责履约网络：Agent 负责理解和拆解，Combo 负责找到有授权、有资源、能担责的结果提供方，并完成交易与证明。**

这个十年形态的前台可能消失；它是否成立，取决于个人 Agent 是否真的采购第三方服务，以及模型平台是否允许独立交易层存在。

## 十四、对外可以讲的一条大 Bet

不讲“行动互联网”，可以讲：

> **我们下注：AI 会把一部分按人时出售的专业服务，变成像软件一样可规模化、但仍由专家拥有品牌、标准和责任的服务产品。Combo 从帮助一个创作者卖出一个结果开始，逐步成为这些 AI-native 专业实践的经营与交易系统。**

这句话同时包含：

- Why now：AI 显著降低重复交付成本；
- 当前用户：有方法、有重复需求、有分发的专家创作者；
- 当前产品：把一项服务变成收费 AI 产品；
- 扩张：多个 SKU、跨专家交易、个人 Agent 采购；
- 反证：若专家差异、付费和持续经营不存在，Bet 失败。
