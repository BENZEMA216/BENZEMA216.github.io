# Combo 内部故事线与 VC 沟通桥接稿

> 查询：把本轮关于人的独特性、Agent、结果交易、内容社区、用户 Context、评价与平台终局的讨论整理成一条内部可相信、对 VC 可解释、同时不伪装确定性的故事线。
>
> 边界：这是内部工作底稿，不替代 [Combo 当前公司叙事](/output/reports/combo/narrative/combo-current-story-2026-07/)。文中的平台、社区、数据网络与五到十年形态均为条件式期权。

## 摘要

本轮可以先收敛为四个对象：

| 层 | Combo 中的对象 |
|---|---|
| 能力对象 | 来自某个人的经验、方法、品味与 Context，被封装为有边界、可持续更新的 Agentic 供给 |
| 交易对象 | 用户真正购买的具体结果，而不是 Agent、判断、责任或协同过程 |
| 学习对象 | 一次真实使用留下的 `用户 Context + Agent / 服务版本 + 结果 + Verdict` |
| 内容对象 | 经授权、脱敏后，一次真实行动中值得旁观、选择和“应用到我”的部分 |
77777
由此形成一条暂时最完整的故事：

> **Combo 让一个人的方法在本人不必每次亲自服务的情况下，由 Agent 应用到另一个人的具体 Context，交付一个可购买的结果；每次使用留下的评价继续改善这项供给适合谁、该怎样交付，并让原能力贡献者从复用中持续获得收益。**

这句话里，已经做出的选择是：

- Combo 不做基础模型，模型是可以替换的生产资料；
- 用户价值是好结果，不是“人和 Agent 协同”；
- 人的名字可以不出现在消费者前台；
- 人的独特性在供给形成、持续纠正和收益归属上仍然重要；
- 交易是价值兑现层，内容 / 社区是需求形成与发现层，联系人是复购和关系层；
- 平台是否真的成立，只能由复购、跨供给购买、站内需求与结果数据增益证明。

真正尚未确定的是：

- 人类差异在什么任务上能够长期优于通用模型；
- 用户为什么以及愿意多付多少钱；
- 内容、货架、联系人与统一入口，哪一个会成为主要前台；
- 用户评价能否稳定改善 Agent 或路由；
- Combo 最终是横向平台、内容社区、垂直结果公司，还是供给侧经营系统。

因此，对这条故事的 buy-in 不应来自“我们知道十年终局”，而应来自：

> **今天的每一步本身能创造价值，并产生足以决定下一步的证据；前一层不成立，就不继续把后一层讲成必然。**

## 一、先把“事实、选择、Bet 和空白”分开

### 1. 当前选择

这些是创始人对公司方向的选择，不等于市场已经证明：

1. **不做基础模型。** Combo 使用不同模型、工具与算力完成履约，但不把模型能力本身作为公司定义。
2. **以结果为商品。** 用户购买的是一份可使用的成品或状态变化；判断、真人介入、重做和退款只是生产与补救机制。
3. **押注人的差异不会完全消失。** 人的经验、方法、品味、关系与动态 Context 可以通过 Agentic 方式继续产生多样化结果。
4. **允许供给者在前台隐身。** 用户只认识 Combo、只关心结果，也可以是成功；但人的贡献、授权与收益关系不能被平台抹掉。
5. **把交易、社区和关系作为公司关注的三层。** 它们不一定是三个产品，也不必现在决定谁是终局首页。

### 2. 高置信度环境判断

- 通用模型会继续增强，普通生成、检索、拆解与编排会越来越便宜；
- 单纯的 Prompt、Agent 目录、通用 Workflow 与模型选择会被快速商品化；
- AI 会降低一部分专业服务的边际交付成本，也会同时压低普通生成结果的价格；
- 大量专业与改善型需求依赖个人 Context，且用户事前未必能准确表达；
- 用户最终会以结果、成本、速度和省心程度评价产品，而不会为“协同”本身付费。

这些判断只说明机会与压力同时增加，不自动推出 Combo 会赢。

### 3. 公司成立所依赖的核心 Bet

1. 至少在一部分有边界的任务中，人的方法、案例与持续纠正会带来相对通用模型可感知、可付费的结果差异；
2. 这种差异可以在不要求本人逐单重做的情况下，被 Agent 重复交付；
3. 带 Context 的真实结果与用户 Verdict，可以改善个性化、供给适配、路由或 Agent 版本；
4. 用户获得一次满意结果后，会继续在 Combo 购买相邻服务、复用 Context 或长期使用某项能力；
5. 真实行动可以产生值得消费的内容，帮助用户发现原本说不出的需求；
6. 人类能力的贡献者愿意授权、持续纠正，并接受一套可解释的收益分配机制。

## 二、Combo 今天到底做什么

当前可对外讲的原子仍然是：

```text
一个已经反复提供某项服务的人
→ 把案例、方法、标准与边界交给 Combo
→ Combo 将其封装为一个可收费的 Agent 服务
→ 用户提交自己的 Context 并付款
→ 人 + Agent 共同交付一个明确结果
→ 用户接受、修改、拒绝或退款
```

### 对消费者

他买到的不是：

- 某个 Agent；
- 一段 Prompt；
- 专家的“判断与责任”；
- 一支动态组织；
- 一次抽象的人机协同。

他买到的是：

> **一份范围、价格、时限和补救方式清楚，可以直接使用的结果。**

### 对能力贡献者

他得到的是：

> **让自己的一部分能力在本人不必逐单亲自完成时仍然可以被使用、被持续纠正并产生收入。**

能力贡献者可以是创作者、专家、普通用户或一个小团队。选择创作者作为第一批供给，是因为他们更容易同时拥有方法、案例、信任和初始分发，不代表终局只服务 KOL。

### 对 Combo

Combo 负责的是：

- 把人的方法变成有边界的服务；
- 组合可替换的模型、工具与真人完成交付；
- 管理用户 Context 的授权；
- 承接支付、交付、修改、退款和收益分配；
- 记录真实使用中的结果与反馈；
- 在证据充分时改善 Agent、适配与路由。

## 三、真正 AI-native 的原子：Run，而不是帖子或商品页

本轮讨论中最有价值的新抽象是一次真实的 `Run`：

```text
一个人的 Context 与目标
→ 调用一个来自人类能力的 Agent / Combo
→ 人 + Agent + 人共同完成一次行动
→ 得到一个具体结果
→ 需求方给出直接 Verdict
```

一条最小记录包括：

```text
Context
+ intent
+ Agent / 服务版本
+ 执行动作
+ 结果
+ Verdict
+ 后续行为
```

用户不必写长评价。由于平台已经知道他的 Context，一句“这版对了”“第二个更好”“不要这种语气”就可能是高价值信号。

但必须区分两件事：

- **一次直接表达，足以更新这个用户的偏好和供给适配判断；**
- **一次直接表达，通常不足以自动修改全局 Agent。**

消费者在这里至少成为一名 evaluator，而不是自动成为新的供给者。只有当他愿意授权一套可复用的方法、经验或能力时，才可能进一步成为供给者。

安全的改进链应当是：

```text
原始反馈
→ 按 Context 聚类
→ 形成候选改动
→ replay / eval
→ 能力贡献者审核或治理规则批准
→ 发布新版本
```

否则平台容易把所有 Agent 优化成平均答案，反而消灭原本想保护的差异。

## 四、同一个 Run 如何同时生成交易、内容和关系

Run 本身不是天然的消费内容。大量成功交付只是有用，不一定值得旁观。

一个最简单的内容性测试是：

> **拿掉价格、“应用到我”和 Combo 品牌后，这段行动是否仍然有人愿意看完、作选择、讨论、收藏或等待下一集？**

只有当一次行动包含以下至少一种张力，它才可能成为内容：

- Before / After 的明显变化；
- 同一 Context 下多个结果的选择；
- 人与 Agent 或多个方法之间的分歧；
- 一次挑战、实验或失败；
- 用户纠正 Agent 后的进化；
- 一个长期项目的连续进展。

最值得优先测试的原生内容单元是：

```text
一个真实处境
→ 2–3 个可能结果
→ 观众先作选择
→ 展示当事人的真实选择与理由
→ 点击“应用到我”
```

并非所有 Run 都应公开。更合理的是三层记录：

1. 私有完整 Run：只用于当次履约与用户可控的历史；
2. 平台学习信号：脱敏、结构化地用于偏好、适配与候选改进；
3. 公开内容卡：只从用户明确授权、可安全脱敏且本身值得消费的 Run 中产生。

因此：

> **所有 Run 都可能产生学习；只有少数 Run 应当成为内容。**

由此，四种产品对象可以被清楚区分：

| 对象 | 用户动作 | 平台价值 |
|---|---|---|
| Run | 完成一次真实行动 | 产生结果与 ground truth |
| 结果 SKU | 购买、验收 | 产生收入 |
| 内容卡 | 看、选择、收藏、分享 | 形成需求与发现 |
| Agent 联系人 | 保留、复用、共同工作 | 形成长期关系与留存 |

同一条链可以是：

```text
看见别人完成了一次行动
→ 认出“这也适用于我”
→ 点击“应用到我”
→ 用自己的 Context 购买结果
→ 给出 Verdict
→ 再次购买或保留该 Agent
→ 经授权生成新的案例内容
```

所以目前不必把 Feed、货架和联系人当作三种互斥终局：

- **Feed** 解决“我还不知道自己需要什么”；
- **货架 / 搜索** 解决“我知道要完成什么”；
- **联系人 / 项目** 解决“我已经找到好用的能力，不想每次重选”；
- **Combo 自动选择** 解决“我只想把问题交出去”。

哪一种成为首页，仍然留空；它应由真实复访行为决定。

## 五、完整故事线：从一个结果到一个网络

### 阶段 0：一人、一项服务、一个结果

当前任务不是证明平台，而是证明：

- 用户愿为明确结果支付；
- 人类方法带来的 Agent 版本比同条件通用模型更好；
- AI 确实降低每单真人分钟；
- 计入退款、工具、客服与分成后仍有正贡献；
- 能力贡献者获得净增量收入。

如果这一层不成立，故事结束。

### 阶段 1：供给侧经营与学习系统

一个人开始经营多个服务，Combo 保存：

- 服务定义与版本；
- 产品、客户、订单与支付；
- Context 授权；
- 交付、修改、退款和人工介入；
- 用户 Verdict 与复购。

此时 Combo 可能只是一家优秀的专家服务产品化与履约 OS，也可以独立成立；还不是 Marketplace 或内容社区。

### 阶段 2：消费者关系开始属于 Combo

关键不是 Agent 数量，而是：

- 用户再次购买；
- 用户购买另一项服务或另一位贡献者的服务；
- 历史 Context 确实让第二次体验更好；
- 用户对 Combo 的信任超过单一创作者深链。

可能发生的信任迁移是：

```text
先信任某个人
→ 愿意尝试他的 Agent 服务
→ 结果满意
→ 开始信任 Combo 的交付与补救
→ 接受 Combo 推荐陌生供给
→ 最终只告诉 Combo 自己要什么
```

人的名字可以在这个过程中逐渐退到后台；这不否定人的独特性，而是说明人的差异已经通过结果完成价值转移。

### 阶段 3：两条可以并存的上行路径

#### 路径 A：结果交易网络

用户有明确目标时，Combo 根据 Context 选择合适供给并完成交易、交付与验收。

成立证据：

- 平台自产需求；
- 跨供给购买；
- 路由显著提高完成率或降低退款；
- 用户不必知道背后是谁，仍然信任 Combo。

#### 路径 B：内容驱动的行动社区

用户没有明确目标时，通过观看真实行动、变化和选择发现需求，并点击“应用到我”。

成立证据：

- 用户无明确订单也会主动回来；
- 真实 Run 低成本、经授权地产生可消费内容；
- 内容带来陌生供给交易与相邻需求；
- 内容排序与满意、复购一致，而不只是制造时长。

交易与内容并不矛盾：

> **交易负责价值兑现，内容负责创造和发现需求。**

#### 关系层：长期 Agent 联系人

如果用户第一次满意后不再重新搜索，而是持续保留和调用同一个 Agent，它会成为留存层：

- 共享长期 Context；
- 跟随持续项目；
- 必要时升级真人；
- 与其他 Agent 协作。

它目前更适合作为“交易后的关系形态”，而不是必须单独押注的第三个公司故事。

### 阶段 4：条件式终局

如果前述路径成立，Combo 可能成为：

> **一个以真实人类差异为供给来源、以结果为交易单元、以 Context-specific Verdict 持续改善的能力网络。**

用户可能只需要表达目标，Combo 自动选择合适的人类衍生 Agent、工具与必要真人，完成结果并结算收益。用户是否看见供给者，不再是成功的必要条件。

这仍不是“逼近 AGI 的网络”。Combo 不追求成为一个全知全能模型，而是让异质的人类能力可以被发现、执行、反馈、组合和结算。

## 六、真正值得对 VC 讲的两条预判

### 预判一：内容会从“可观看”变成“可应用”

传统内容平台的终点是观看、互动或购买标准商品。Combo 的 Bet 是：

> **一次真实的人类行动，可以被另一个人带着自己的 Context 重新执行。**

因此最有潜力的消费者体验不是“AI 生成更多帖子”，而是：

```text
看别人怎么改变
→ 判断是否适合我
→ 点击应用到我
→ 直接获得自己的版本
```

### 预判二：消费会开始改进供给，而不只改进排序

传统电商评价主要改变排名；Combo 希望每次消费留下的 Context 与 Verdict 同时改善：

- 这个用户喜欢什么；
- 哪个 Agent 适合哪类 Context；
- 服务边界应如何调整；
- 哪个候选 Agent 版本更好。

这条 Bet 如果成立，Combo 就不只是“旧平台 + AI”，而是：

> **每一次消费，都在帮助产生下一次更合适的供给。**

它的风险同样清楚：反馈稀疏、结果不可归因、隐私限制或错误优化，都可能让这条飞轮不成立。

## 七、给 VC 的故事：Base Case、Upside 与 Option

### 30 秒版本

> 很多有专业能力的人，只能卖课或亲自按小时服务。Combo 帮他们把一项反复提供的服务，做成范围、价格和交付物清楚、由 AI 完成大部分交付的服务产品。用户提交自己的 Context，购买的不是课程或聊天机器人，而是一份具体结果；真人只处理必要例外。我们不做基础模型，而是拥有服务定义、交易、交付和反馈闭环。小鹅通把专家知识做成课程，Combo 把专家服务做成可以反复卖的 AI 产品。

### 为什么可能变大

> 如果真实订单能够持续改善 Agent 与 Context 的适配，Combo 会从服务产品化工具变成结果交易网络；如果真实交付又能生成值得观看和“应用到我”的内容，它还会获得自己的需求入口。长期，用户可能不再挑选专家，只把目标交给 Combo，由平台自动选择合适的人类衍生 Agent 并完成结果。

### VC 回报结构

| 层级 | 公司形态 | VC 需要看到的证据 |
|---|---|---|
| Base Case | 专家服务产品化与履约工具 | 真实支付、正贡献毛利、专家持续经营 |
| Expansion | 产品、订单、客户、履约与支付的 system of record | 第二 SKU、90 / 180 日留存、迁移成本 |
| Network Upside | 跨供给结果交易网络 | 平台自产需求、跨供给购买、路由增益 |
| Consumer Upside | 内容驱动的行动社区 | 非交易复访、内容到订单、真实内容供给 |
| Long-range Option | 用户或个人 Agent 的自动采购入口 | 机器可读服务、授权采购、验收与结算 |

VC 不需要一次相信全部终局。更可信的融资表达是：

> **我们正在用一个可验证的服务切口购买后面几层期权；每层都有独立价值，也有明确解锁条件。**

## 八、未来 6–12 个月应该用什么决定故事分叉
