# 互联网产品范式史：从 Page、Feed 到 Agent Run（2000–2026）

> 查询：从 2000 年开始，互联网产品究竟如何发展；这段历史能否形成一套牵引 Combo 产品巧思的历史观。
>
> 口径：本文不是公司兴衰史，也不是融资周期或纯技术史，而是产品范式史。年份表示机制成为主流产品变量的大致窗口，各阶段彼此重叠。美国互联网提供了较完整的公开资料主线，中国互联网则在交易信任、超级 App、移动支付、Mini Program 与 interest graph 上形成了重要的压缩路径。

## 核心结论

> **过去二十五年的互联网产品史，是不断把新的现实对象变得可计算，并持续缩短“产生意图”到“得到结果”的距离。**

互联网先后把这些对象装进了产品：

```text
网页与 Query
→ 身份、关系与 Post
→ App、位置与设备 Context
→ Feed item、注意力与行为信号
→ Order、供给与履约状态
→ Workspace、Record 与工作流
→ Prompt、Artifact 与用户意图
→ Task、Run、Trace 与 Outcome
```

相应地，产品替用户承担的责任越来越重：

```text
给你入口
→ 帮你找到
→ 帮你发现
→ 帮你连接和交易
→ 帮你持续工作
→ 帮你生成
→ 帮你行动
→ 尝试对结果负责
```

这不是后一层消灭前一层。Search、Feed、App、Marketplace 和 SaaS 都还存在；历史更像地层，新范式把旧能力收进更完整的行为闭环。

## 一、2000–2003：先解决“找到”与“敢交易”

互联网泡沫破裂没有证明互联网无用，反而清除了只靠流量想象、没有稳定用户价值和收入机制的产品。O’Reilly 后来把这次震荡视为 Web 2.0 的转折点：网络本身开始成为平台，而不是一批待售网页。

这一阶段有两个决定性的产品发明：

1. **Search 把用户明确表达的意图变成入口。** Google 在 2000 年推出自助 AdWords，广告只在相符 Query 下出现。搜索第一次同时形成了高质量用户动作和可持续商业模式。
2. **Marketplace 把陌生人交易变成产品化信任。** 商品 Listing 之外，评价、支付、托管和争议处理共同构成交易协议。中国的淘宝与支付宝也走出类似路径：支付宝的 escrow 不是支付按钮，而是对陌生交易结算风险的产品回应。

因此，这一代的核心不是“门户变成搜索框”，而是：

> **把已经存在的需求识别出来，再用信誉与支付把点击推进为交易。**

## 二、2003–2007：用户从受众变成供给者

宽带、浏览器应用和数字媒体降低了发布成本，Blog、Wikipedia、Flickr、YouTube 等产品不再只编辑内容，而是设计一套让用户持续贡献的机制。Post、Profile、Tag、Comment、Subscription 和 Embed 成为新的产品原子。

Web 2.0 的深层变化不是页面更动态，也不只是 UGC，而是：

- 服务随使用持续更新，而非发售固定软件包；
- 用户行为本身补充数据和供给；
- 每个参与者让产品对下一个参与者更有价值；
- 产品公司开始经营“参与式架构”。

YouTube 2007 年扩展 Partner Program，又把用户供给与广告收入连接起来。个人不再只是免费上传者，开始成为可以持续经营的生产者。

## 三、2006–2010：关系图成为分发基础设施

当用户和内容同时爆炸，“谁发布了什么”已不足以构成产品，新的问题是“什么应该先到达谁”。

Facebook 在 2006 年把朋友的零散行为聚合成持续更新的 News Feed，2007 年又把 Social Graph、Feed 分发与第三方应用结合成平台。这里出现了三个长期控制点：

```text
身份
→ 关系
→ 分发
```

产品原子由孤立页面变成 `人 + 行为故事 + 关系上下文`。用户不再每次先产生 Query，内容可以沿关系主动来到用户面前。

与此同时，AWS 在 2006 年将计算资源变成可随时扩缩、按使用付费的服务。Cloud 的历史意义不只是服务器更便宜，而是小团队不再先购买基础设施，产品可以持续部署、快速扩张，并通过 API 组合更多能力。

## 四、2008–2013：Mobile 不是小屏网页，而是互联网进入现场

iPhone、App Store 和随后普及的智能手机，把持续身份、相机、位置、通讯录、触摸、Push 和支付放进同一设备。Apple 在 2008 年给开发者提供统一 SDK、无线分发和收入分成，App 由此成为一套完整的产品与商业容器。

真正的迁移是：

```text
访问一个网站
→ 安装一个随身行为入口
```

产品开始知道用户身在何处、此刻发生了什么，并能在用户没有主动打开浏览器时发起提醒。使用也从少数长会话变成全天候的微时刻。Instagram、Uber 等 mobile-first 产品并非桌面产品的缩小版；没有相机、位置、Push、支付和持续登录，它们的核心行为就不存在。

## 五、2012–2017：平台开始分配注意力，也开始协调现实履约

移动内容供给超过人的主动筛选能力后，Feed 获得排序权。早期算法主要在 Social Graph 提供的候选内容里决定顺序；到短视频与 interest graph，单条内容可以脱离既有粉丝关系被独立测试和路由。

同一时期，GPS、移动支付、Cloud 和消息系统把现实世界的供给变成可计算状态：

```text
可用供给
→ 匹配
→ 下单
→ 调度
→ 支付
→ 履约
→ 评价 / 退款 / 保障
```

Uber、Airbnb 一类产品的创新并不只是“把司机或房东放上网”，而是把等待时间、库存、身份、价格、订单状态和信用组织成可运行的市场。产品原子由信息 Listing 变成有状态、可追责的一笔 Trip、Stay 或 Order。

这也是互联网第一次大规模从“组织符号世界”走向“协调现实行动”。

## 六、2014–2021：软件占据工作流，个人成为可经营供给

消费互联网与企业互联网在这一阶段形成两条并行支流。

在企业侧，SaaS 不只是把许可证改成订阅，而是通过 Workspace、Record、Channel、API event 和 Integration 占据团队持续工作的共同状态。软件由单点工具变成组织运行环境，商业模式才自然表现为 Seat、Usage 和增值服务。

在中国，微信把社交身份、支付、二维码和 Mini Program 放在同一超级 App 内。腾讯 2018 年报告描述 Mini Program 可通过聊天入口、搜索与线下二维码连接服务，并支持即时部署。它压缩了独立 App 的“发现—安装—注册—支付”链路，但依赖特定的支付、分发与操作系统环境，不是所有市场的必然终局。

在供给侧，算法分发、移动创作、会员、直播、电商与支付分账让 Creator 从流量节点逐渐变成微型企业。可经营的最小单位不再只有 Content，也包括 Membership、Course、Digital good、Appointment 和 Service offer。

这一阶段真正形成的是：

> **互联网不只分发内容，也开始管理供给者的客户、交易、履约和经营状态。**

## 七、2022–2024：自然语言从内容输入变成软件控制层

ChatGPT 在 2022 年把多轮自然语言对话做成大众产品：用户不再学习菜单和固定命令，而是直接描述意图、追问和迭代。产品原子从页面或表单变成 `Turn / Session / Artifact`。

Copilot 随后进入 IDE、客服、办公和创作工具。通用 Chat 解决“模型能不能回答”，嵌入式 Copilot 解决“模型是否知道我正在做什么”。因此，这一代真正稀缺的不是生成能力本身，而是：

- 当前文件、代码库、客户与业务状态；
- 权限与组织知识；
- 正确性、可编辑性和用户判断；
- 是否嵌入一个高频、已有预算的工作流。

生成式 AI 让内容和初稿供给激增，也把价值向 Context、选择、验证和最终用途推高。

## 八、2024–2026：软件开始从“给答案”走向“代行动”

Agentic 产品把模型与检索、记忆、工具和环境操作结合起来。Anthropic 区分了两种形态：Workflow 沿预定义路径组织模型与工具，Agent 则动态决定过程与 Tool use；同时也明确提醒，Agent 往往以更高延迟和成本换取任务表现，很多场景并不需要 Agent。

因此，Agent 时代最重要的变化不是聊天框里出现一个新名字，而是产品责任边界变化：

```text
Answer：我告诉你可能怎么做
Copilot：我在你的工作现场协助你做
Agent：你授权我采取多步行动
Outcome product：你按约定标准验收我做成了什么
```

一旦软件能改文件、发消息、使用账户、下单或修改业务状态，核心问题就从答案质量迁移到：

- 允许它做什么；
- 过程是否可见、可暂停、可恢复；
- 失败后谁补救；
- 什么证据证明任务完成；
- 谁对损失和最终结果负责。

截至 2026 年，`Run / Trace` 已是清晰的产品原子，`Verified outcome` 仍主要是方向而非成熟行业事实。

## 三条跨阶段的历史规律

### 1. 每一代都把上一代的稀缺品变成基础设施

```text
能接入网络
→ 能找到相关信息
→ 能获得独有供给和关系
→ 能争夺注意力与主屏入口
→ 能完成交易和现实履约
→ 能占据工作流和客户关系
→ 能理解 Context 并可靠执行
→ 能证明结果、承担责任
```

创业机会通常不在继续售卖已经便宜的东西，而在承接被推高的下一层稀缺。

### 2. 分发越来越接近用户真正要完成的事

```text
编辑选择：大家应该看什么
→ Search：你明确说要找什么
→ Social graph：你认识的人在做什么
→ Recommendation：系统推测你会喜欢什么
→ Chat：你直接描述想要什么
→ Agent routing：系统判断该调用什么能力替你完成
```

每一次分发升级都增加便利，也把更多解释权和控制权交给平台。Agent 若成为入口，争夺的将不只是注意力，而是用户意图、采购权与行动权。

### 3. 伟大产品不是展示新技术，而是创造一个以前不存在的默认动作

Search 的巧思是把意图放进 Query；Feed 把零散行为编译成可连续消费的 Story；App Store 把开发、分发和支付装进一个容器；Marketplace 把线下服务变成 Order 状态机；Chat 把自然语言变成控制界面。

所以，面向 Agent 的产品设计问题不应是“哪里加一个 AI 按钮”，而应是：

> **什么新的完整动作，因为模型、Context 和工具调用而第一次能变成默认行为？**

## 中国互联网不是旁支，而是三次关键压缩

1. **淘宝 + 支付宝压缩了发现、信誉与结算。** 2003 年的淘宝与 2004 年的支付宝 escrow 针对的是陌生人交易不敢付款的问题。
2. **微信 + 微信支付 + 二维码 + Mini Program 压缩了 App economy。** 用户可以从关系或线下场景直接进入轻服务、支付并复购，不必先下载安装独立 App。
3. **抖音 / TikTok 的 interest graph 压缩了供给冷启动。** 内容是否获得分发不再直接取决于账号原有粉丝量，单条 Item 的行为反馈成为主要路由信号。

这三次压缩分别把交易、服务和分发的摩擦降到新的数量级，也解释了中国产品史不能只用美国的 Website → App → SaaS 路线描述。

## 这条历史怎样牵引 Combo

Combo 可以采用这样一版历史观：

> **互联网先把信息、关系、注意力、交易和工作流数字化；AI 正在把人的方法与执行过程变成可运行对象。当软件从“给人一个界面”转向“获得 Context 后替人行动”，新的稀缺就不再是内容、工具或 Agent 数量，而是哪个方法适用于哪个人、能否在真实 Context 中做成、如何验收，以及谁授权、获益并对失败负责。Combo 要把真人衍生的方法做成有边界、可执行、可验收、可购买的结果 Run。**

它比“Agent 会越来越多，所以需要 Agent Marketplace”多出三个关键连接：

1. **产品史连接：从可观看，走向可应用。**
   传统内容让用户看见一个人怎么做；Combo 的关键动作应是“应用到我”，把同一方法带入用户自己的 Context。

2. **经济史连接：从卖工具和工时，走向卖有边界的交付。**
   用户不购买 Agent、Prompt 或“人的独特性”这些抽象物，而购买范围、价格、时限、交付物和失败补救都清楚的服务结果。

3. **制度史连接：行动越真实，越需要来源、授权、验收与分配。**
   如果供给来自真人的方法、案例和持续纠正，产品必须记录谁贡献、允许怎样使用、何时撤回、如何分账；但这些机制最终仍要转化为更好的用户结果。

### 由历史直接推出的六个产品巧思

| 历史机制 | 不应照搬什么 | Combo 应提炼什么 |
|---|---|---|
| Search 捕捉明确 Query | 只做 Agent 搜索框 | 把模糊目标澄清成可购买的 Result brief |
| Feed 形成潜在需求 | 先做泛内容流、追停留时长 | 用真实 Before / After 案例触发“这也适用于我” |
| Marketplace 把供给变成订单 | 陈列大量 Agent 卡片 | 把输入、范围、交付物、验收与补救写成 Result contract |
| SaaS 占据持续工作流 | 卖一个一次性 Prompt | 保存客户 Context、版本、返工、支付与长期项目状态 |
| Agent 执行多步动作 | 把“自主”当卖点 | 展示 Run、关键决策、授权点、失败恢复与真人升级 |
| Recommendation 用行为改善路由 | 只用点击、点赞、停留训练排序 | 用 `Context + Run + Verdict` 判断什么方法在哪类情境真正有效 |

因此，Combo 最有辨识度的产品循环不是一个 Agent 商店，而可能是：

```text
真实交付
→ 经授权生成案例
→ 相似用户识别自己的问题
→ 点击“应用到我”
→ 绑定私人 Context
→ AI + 必要真人完成一次有边界的 Run
→ 用户按约定验收
→ 新结果改善能力版本与下一次路由
```

这里，Content、Software、Service 不再是三个割裂品类，而是同一项能力的三种状态：

```text
公开案例：我看见它如何解决问题
→ 可执行方法：系统知道如何应用
→ 私人 Run：它在我的 Context 中执行
→ 结果与 Verdict：我判断它是否做成
```

KOL 是最初的信任与分发楔子，不是这套历史观的主角；五阶段路线是验证上述连接是否成立的证据计划，也不是历史必然。

## 必须保留的反证

- **Agent 不一定取代 App、Search 或 Feed。** 新范式会叠加旧入口；很多稳定任务用确定性 Workflow 更便宜、更可靠。
- **“人的经验可执行”尚未成为成熟供给机制。** 隐性知识提取、动态更新、授权和收益分配仍没有统一标准。
- **通用模型可能吸收大部分方法与编排。** 真人衍生供给只有在同条件下带来可测的质量、成本、成功率或复购增益时才成立。
- **按结果收费只适合边界与验收较清晰的任务。** 品牌、咨询、健康和长期经营结果常常难归因，可能只能按阶段交付、Resolution 或混合模式收费。
- **结果数据不自动产生网络效应。** 它必须真实、可比较、能改善下一次供给或路由，并防止刷结果与 Goodhart’s law。
- **行动权会带来新的平台集中风险。** 如果模型入口掌握意图、身份、支付和 Tool routing，垂直产品必须拥有独特工作流、结果记录或客户关系，才不只是可替换插件。
