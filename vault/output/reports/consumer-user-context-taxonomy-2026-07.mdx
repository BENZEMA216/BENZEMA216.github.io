# C 端用户重要 Context 分类

> 回答问题：「一般而言，大家认为 C 端用户有哪些 Context 是重要的？」

## 一句话结论

C 端最重要的不是「用户资料越多越好」，而是四类能直接改变 AI 结果质量的 context：**当前触发处境、任务/工作流状态、长期偏好与身份、可信可授权的个人数据**。真正有商业价值的 context，通常出现在用户从 casual asking 进入「高频工作流」或「高赌注、不熟悉、信任敏感」任务的那一刻。

## 核心分类

| Context 类型 | 具体内容 | 为什么重要 | 典型产品价值 |
|---|---|---|---|
| **1. 当前触发处境** | 用户现在为什么来：问信息、求建议、让 AI 执行、表达情绪；任务是否紧急、是否高赌注、是否不熟悉 | 决定回答应该是搜索式、顾问式、执行式还是陪伴式 | 影响转化和付费：普通浏览很难付费，高赌注触发更可能付费 |
| **2. 当前任务 / 工作流状态** | 当前项目、目标、输入材料、进度、待办、约束、上一步结果、失败记录 | 决定 AI 能不能「接着做」，而不是每次重来 | 影响留存：能嵌入高频工作流，才不是一次性 chatbot |
| **3. 长期身份与角色** | 职业、技能水平、生活阶段、家庭状态、地域文化、语言、收入/消费力大致区间 | 决定建议的默认假设是否贴身 | 用于 onboarding、默认模板、推荐和分层 |
| **4. 偏好 / 品味 / 决策风格** | 输出格式、语气、审美、品牌偏好、风险偏好、信息密度、喜欢/反感的方案 | 决定个性化体验是否真的省心 | 让用户感觉「它懂我」，减少重复 prompt |
| **5. 历史对话与行动轨迹** | 过去问过什么、试过什么、决定过什么、哪些只是 try、哪些是 commitment、未关闭 open loop | 防止 AI 健忘，也防止重复建议 | Personal Knowledge Card / Conversation Wiki 的核心资产 |
| **6. 私人领域数据** | 日历、邮件、位置、消费、健康、理财、家庭后勤、账号状态、文件 | 让 AI 从「建议」进入「替你做事」 | Agent 执行的前提，但权限和隐私成本最高 |
| **7. 社交与关系 context** | 家人、同事、朋友、受众、合作关系、谁信任谁、谁会受到影响 | 很多 C 端任务本质是关系任务，不是纯信息任务 | 陪伴、家庭、协作、内容发布、招聘/合作场景 |
| **8. 情绪与认知状态** | 焦虑、困惑、信心、疲惫、是否需要安抚或直接决策支持 | 用户明确想要 emotionally intelligent AI | 陪伴、心理支持、健康/理财导航里尤其重要 |
| **9. 信任与 provenance** | 这条记忆从哪来、何时产生、用户是否确认、置信度、是否过时 | 陈旧记忆可能比没记忆更糟 | 建立用户信任，减少错误个性化 |
| **10. 运行环境 / 交互面** | 设备、位置、时间、当前 App、输入方式、是否在移动端、是否适合主动提醒 | 决定 AI 能否 ambient / anticipatory | 从 chatbot 变成后台助手或场景内助手 |

## 产品上更实用的分层

**L0：稳定人格层**
身份、语言、长期偏好、禁忌、价值观、风险偏好。适合少量常驻，但必须可编辑、可删除、可溯源。

**L1：当前任务层**
当前目标、输入材料、约束、阶段、deadline、上一步结果。最应该优先进入上下文，因为它直接影响本轮输出。

**L2：历史轨迹层**
过去的探索、决定、失败、open loops、内容资产。适合按需检索，不应全量塞进窗口。

**L3：私有数据层**
日历、邮件、健康、理财、家庭、账号权限。价值最高，但权限、隐私和误操作风险也最高，应按任务授权。

**L4：信任与关系层**
谁说的、谁验证过、用户是否确认、与谁相关、是否会影响他人。高赌注任务必须有这一层。

## 判断一个 Context 是否值得收集

一个 context 值不值得进入产品，最好问五个问题：

1. 它是否会改变 AI 的答案或行动？
2. 它是否能减少用户重复解释？
3. 它是否能让 AI 进入一个高频工作流？
4. 它是否能支撑高赌注场景里的信任与验证？
5. 它是否能被用户看见、编辑、撤回，而不是变成黑箱记忆？

如果五个问题都答不上来，它多半只是「画像噪音」，不是有价值的 context。

## 与 C 端 AI 的几条对应关系

- **个性化**最依赖：身份、偏好、历史轨迹、provenance。
- **留存**最依赖：任务 / 工作流状态，而不是静态 persona。
- **付费**最依赖：高赌注触发处境、可信经验、验证证据。
- **Agent 执行**最依赖：私有数据、权限、当前状态、失败恢复。
- **陪伴 / 情感**最依赖：关系、情绪状态、长期互动历史。
- **隐私信任**最依赖：用户可见的记忆管理、来源标注、衰减机制。

## 风险提示

C 端 context 最大的坑是把「记住用户」理解成无限累积。更合理的方向是：**热 context 常驻、温 context 按任务加载、冷 context 可检索、过期 context 自动衰减**。否则系统会从「懂我」变成「拿旧记忆误判我」。
