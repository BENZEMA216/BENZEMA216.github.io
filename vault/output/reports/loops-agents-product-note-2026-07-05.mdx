# Loops Agents 产品速记

> 结论：Loops Agents 不是一个新的通用 Agent 平台，而是 Loops 这家 email SaaS 给 AI coding agents 开的集成入口：让 Claude Code / Codex / Cursor 这类 agent 更容易把 Loops 接进产品代码里。

## 它在做什么

Loops 本体是面向 SaaS / product teams 的 email platform，覆盖 contacts、events、segments、transactional email、marketing campaigns、workflows 和 API/SDK。`loops.so/agents` 这一页是在把这些能力包装成 agent-friendly developer surface。

具体说，它想让 AI agent 帮开发者完成这些事情：

- 在项目里安装 Loops SDK / CLI。
- 配置 transactional email，例如 magic link、welcome email、billing notification。
- 把用户 signup、activation、payment 等事件从应用代码同步到 Loops。
- 迁移已有 email stack。
- 用 Loops 的 API/CLI/SDK 查询、测试、调试 email 集成。
- 未来通过 MCP 和 agent slash commands 进一步降低接入摩擦。

## 当前已发布与未发布

官网页面把能力分成几类：

- 已发布：Skills、Platform API、CLI、LMX、Campaign API、Transactional API、SDKs。
- 即将推出 / 下一步：Workflows API、`/setup` slash command、`/migrate` slash command、MCP。

所以当前更准确的判断是：Loops 已经把 API / CLI / skills / SDK 文档做成 agent 可消费材料；Agents 页把 MCP 标为 `Next`，Quickstart 也说明公开推荐设置仍是 CLI + skills。如果环境需要单独 MCP server 或 private integration，需要联系 Loops support。

## 产品本质

这是典型的 SaaS vendor 把 onboarding 做成 "agent-native integration package"：

- 面向人：官网仍然卖 email platform。
- 面向 agent：提供 CLI、skills、LLM 可读文档、API surface 和未来 MCP。
- 目标动作：不是让用户在 Loops 里聊天，而是让用户在 coding agent 里说"把 Loops 邮件接上"，agent 能直接改代码、调用 CLI、验证结果。

换句话说，Loops Agents 的核心不是 "agent 帮你写邮件文案"，而是 "agent 帮你把邮件基础设施接进你的产品"。

## 对 Agora / Agent Capability Package 的启发

Loops 是一个很好的信号：垂直 SaaS 正在把自己的接入流程拆成 agent 可安装、可调用、可验证的 capability package。

它验证了几个方向：

- `Skills + CLI + API docs` 会成为 SaaS 分发的新入口。
- SaaS 的 developer onboarding 会从 "读文档自己接" 变成 "agent 读技能包并直接改代码"。
- vendor 自己能解决自己的 integration package，但不会自然解决跨 vendor 的 discoverability、entitlement、payout、buyer-specific proof、event ledger。

所以它对 Agora 的含义不是直接竞争，而是供给侧样板：未来每个 SaaS 都可能提供自己的官方 agent package；Agora 要做的应是把这些能力包拿到一个更高层的交易、验证、路由和交付网络里。
