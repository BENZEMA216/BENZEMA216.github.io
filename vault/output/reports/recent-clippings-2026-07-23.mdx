## 主题整理

### 1. Agent 协作的瓶颈从“写 prompt”转向“共同发现未知项”

Fable 实践把 prompt 和 context 比作 map，把真实代码库与业务约束比作 territory。两者差距不会靠一次 planning 自动消失，应在实现前用 blind-spot pass、prototype、interview 和 reference 暴露，在实现中用 implementation notes 记录，在完成后用 explainer 与 quiz 验收。

关键转变是：Spec 不是终点，而是当前已知项的临时合同。Agent 与人真正需要共同管理的是会改变架构、产品方向和验收标准的 unknowns。

### 2. MCP 已有大规模 Registry，但 discovery 远未等于 trust

MCP Census 在 2026-07-07 的快照中统计 15,382 个去重 Server，7,203 个提供 remote endpoint；同时报告 16% 有可核实问题、严重长尾、共享 repo metadata 和名称冲突。它修正了知识库中“Registry 仍是未来事项”的旧表述。

生态下一阶段的控制点不是继续堆目录，而是 publisher identity、package/repo provenance、维护状态、credential scope、运行证据与撤销机制。

### 3. Growth Engineering 是“技术 × 渠道 × 数据”的业务实验系统

YouMind 案例把增长工程定义为用技术对 AARRR 负责，核心循环是需求假设、低成本 MVP、内容分发、漏斗观察和继续/停止判断。集合站、SEO、Chrome Store、Product Hunt 都只是渠道；高流量若不连接目标用户与付费需求，不构成有效增长。

对 Combo 的可迁移结论不是立刻复制提示词站，而是：任何创作者分发实验都必须追到明确服务结果、真实订单、退款和复购；流量不能替代需求证据。

### 4. 真实工作流正在成为 Agent 改进的数据面

真实工作轨迹能保留历史状态、工具依赖、组织规则、异常分支与用户反馈，比纯人造任务更接近 long-horizon 工作。应用公司的工作流入口可能产生稀缺的 agentic trajectory data，但只有补齐 intent、outcome、QA、lineage、privacy 与 eval，日志才可能成为改进资产。

短期更现实的路径是先用轨迹修复 Harness、routing、memory 和 tests；只有当“数据独特性 × Eval 清晰度 × 任务频率 × 单次改善价值”足够高时，企业 post-training 才可能成立。

### 5. “持续学习”与“World Model 是否主线”仍是开放争议

媒体汇编中的梁文锋语录提出 `CoT → Agent → 持续学习 → AI 自迭代 → 具身` 路线，并将 world model、视频生成和 3D 排除在 DeepSeek 主线之外。这是值得记录的产业反方观点，但来源不是官方逐字稿，不能推翻现有 World Model 研究。

更稳定的知识边界是：memory/context 保存和检索经历，不等于模型持续学习；policy distillation、post-training 或其他权重/策略更新才涉及行为能力的持续改变。
