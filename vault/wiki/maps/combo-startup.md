# Combo 创业项目全景

> Combo 当前是一款面向垂类创作者的 AI Service Launcher：把创作者反复提供的专业服务，变成可收费、可规模化交付的 AI 产品。未来 thesis 是从 Launcher 连续生长为 AI-native Practice 的经营与交换网络；Agora 是历史研究代号，不代表当前已经成立的平台。

## 概览

### 当前定位与目标路径：创作者变现工具

- **客户与首阶段分发者**：有专业能力、重复咨询和私域触达能力的垂类创作者 / KOL。
- **最终消费者**：因一个明确需求，从创作者内容、主页或私域进入具体 AI 服务的粉丝。
- **Combo 的目标角色**：帮助创作者提取和封装方法，提供运行、权限、计量、支付、结果交付与售后所需的产品层。
- **首阶段目标路径**：`创作者内容 / 主页 / 私域 → 一个明确 AI 服务 → 粉丝付费使用 → 结果与反馈`。
- **当前目标**：在一个垂类里，用 3–5 个创作者跑出真实上线、付费、交付、退款、复购和创作者收入。

当前已经确认的是公司定位、目标用户和工程方向；完整支付、退款、结算与售后体验尚未被真实订单验证。当前表达真源见 [combo-current-story-2026-07](/output/reports/combo/narrative/combo-current-story-2026-07/)；融资会谈形成的证据与风险见 [combo-investor-learning-synthesis-2026-07-17](/output/reports/combo/fundraising/combo-investor-learning-synthesis-2026-07-17/)。

### 产品机制：让专业服务可规模化交付

Combo 计划验证的产品机制包括：

1. 从内容、私信问答、直播、咨询记录、课程、文档、Session 与隐性经验中识别可复用方法；
2. 将方法封装成输入、输出、适用边界、评价标准和升级到真人的条件；
3. 提供 Runtime、权限控制、计量、支付、结果交付、退款与更新；
4. 记录最小必要的运行证据，支持结果评价和服务改进。

“从 Coding Agent Session 提取 Agent”只是导入方式之一，不是公司定义；加密、Runtime 和支付是产品机制，也不能在没有真实数据时直接称为护城河。

2026-08-03 的 [combo-knowledge-agent-live-dialogue-check-2026-08-03](/output/reports/combo/product/combo-knowledge-agent-live-dialogue-check-2026-08-03/) 证明公开问答 surface 至少能够在 `knowledge_grounded / general_reasoning / insufficient_evidence` 之间分流并维持连续会话。它是 evidence-aware Agent surface 的技术证据，不是创作者服务、支付、履约、退款或复购已经成立的经营证据。

### 未来平台 thesis：一条连续主线

- **Category**：`AI-native Service Commerce`
- **Wedge**：`Agent Miniapp / AI Service Launcher for Provider-owned Practices`
- **Target Platform**：`AI-native Practice Operating & Exchange Network`
- **Main spine**：`Launcher → Practice OS → Service Extension Economy`
- **Conditional upside**：Content-to-Outcome、Outcome Demand、Embedded Service Commerce Infrastructure 与 Agent Procurement Rail

这条主线要求 Provider、Service Product、客户、订单、运行结果与经营历史沿同一 Service Object 连续演化；如果每一层都需要重建供给、数据与分发，就不是平台扩张，而是多次重新创业。完整未来见 [combo-platform-future-vision-and-evolution-2026-08-03](/output/reports/combo/narrative/combo-platform-future-vision-and-evolution-2026-08-03/)，32 轮正反复审与最强 Bear 见 [combo-platform-opportunity-forward-reverse-bp-thesis-2026-08-03](/output/reports/combo/fundraising/combo-platform-opportunity-forward-reverse-bp-thesis-2026-08-03/)。

### 平台叙事与平台事实：达到证据门槛后才合并

Combo 可以讲条件式平台未来；只有同时出现以下行为，才可以把它写成已经从创作者工具升级为平台：

1. **Practice OS 连续性**：Provider 在订单之间持续经营多项服务，并对经营状态产生 recurring WTP；
2. **Extension Economy**：独立 Partner 的扩展一次开发、多家 Practice 复用，并形成真实 Partner P&L 与治理；
3. **跨创作者复用**：同一用户购买第二、第三个创作者服务，并能复用已授权的 Context；
4. **新增需求**：Combo 能给创作者带来私域之外的新增付费需求，平台内生 GMV 开始出现；
5. **路由变好**：Context、运行结果、退款和评价持续改善跨服务匹配与组合。

平台跃迁不由 Agent 数量、Feed 或 Marketplace 页面证明，而由 `跨创作者购买 + 平台新增需求 + 结果驱动路由` 证明。机制详见 [creator-tool-to-capability-network](/wiki/connections/creator-tool-to-capability-network/)。

Agora 研究了 Agent Capability Package、可验证交付、Context Network、event ledger、跨 runtime 分发和结算。这些仍是有价值的长期机制与技术资产，但目前应按以下方式使用：

## 开放问题

1. 首轮候选已收敛为“AI 原生专业视觉创作者”；第一个明确服务结果是什么，这个候选是否能通过真实付费验证？
2. 通用模型已经存在时，用户为什么仍愿意单独付费并再次回来？
3. 创作者愿意授权哪些材料，哪些必须保持本地、可撤回或只用于一次任务？
4. 单任务贡献毛利能否覆盖共创、推理、支付、退款与售后？
5. 何时出现第一笔跨创作者购买和第一笔平台内生 GMV？

7. 哪一类独立 Partner 扩展能被多家 Practice 复用并形成正向 Partner P&L？
